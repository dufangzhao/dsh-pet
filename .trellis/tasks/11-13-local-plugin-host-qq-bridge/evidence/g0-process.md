## Implemented ownership and fixed entry

- [Headless role entry](../../../../apps/desktop/src/local-host/main.ts): `runLocalHostElectron({profileDirectory,packageVersion,createKernel})` sets a separate application name/userData/single-instance lock and creates no BrowserWindow. Call it without blocking Electron's ESM module evaluation on `app.whenReady()`. There is no parent-IPC disconnect shutdown handler.
- [Daemon composition](../../../../apps/desktop/src/local-host/daemon.ts): `startLocalHostDaemon` consumes the actual `LocalPluginKernel` factory. Stop awaits real `kernel.close()`, management socket closure and exact rendezvous retirement before process exit. A failed managed close remains failed rather than claiming settled/stopped.
- [Native client/launcher](../../../../apps/desktop/src/local-host/client.ts): `attachLocalHost` / `startOrAttachLocalHost` use a captured private record and expected package version; the bundled launch descriptor is Main-only. Startup uses detached/unref with no parent IPC. `client.close()` detaches only; it does not call kernel.close, erase source keys or change the Agent link. A failed existing-host proof is not permission to PID-kill or silently take over.
- Parent owns final production build/index wiring and the source-only G2 native-controller composition. This entry takes a host-private factory; it does not invent functional native ports or load a renderer-supplied module/command/path. The controlled fixture supplies the real composition described below.

## Management and private rendezvous

[Node-only rendezvous](../../../../packages/local-host/src/rendezvous.ts) extends the canonical `LocalHostRuntimeIdentity` with format1, fixed IPv4-loopback endpoint and a fresh256-bit management capability. It contains no Agent bearer or QQ key. Stable nonsecret host ID is separate from fresh boot identity. POSIX protection checks parent/file realpaths, actual UID/mode, regular-file/no-link constraints, bounded read, inode stability and exact publisher-owned retirement. Publication is atomic under the native profile singleton; an old boot cannot remove its replacement.

[Management](../../../../packages/local-host/src/management.ts) uses a fresh server/client nonce and domain-separated HMAC proofs over protocol/package/host/boot/session. A PID, anonymous pipe or unauthenticated localhost status is insufficient. After mutual proof, the existing ControlEndpoint runs only `local-host.status` and `local-host.stop` with closed null payloads, bounded64KiB framing/queues/pending work and fixed errors. No arbitrary RPC/HTTP/command/capability dispatch or browser CORS server is exposed. The capability never enters status, renderer URLs or logging.

G0 methods receive no Agent/QQ secrets. Future secret handoff must use the existing SensitivePeer lane mapped to actual daemon tasks; authentication alone is not a task/credential grant. That integration is not claimed by these lifecycle tests.
