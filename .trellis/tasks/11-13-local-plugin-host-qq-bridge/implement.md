# Ordered implementation — local host / remote Agent

Planning only. Product scope is [the PRD](prd.md), ownership/protocol decisions are [the design](design.md). No product implementation starts until the user reviews this final plan. Do not treat research notes as additional SDK APIs.

## Sequence and gates

### G0 — Prove the host, wire and distribution skeleton

- Confirm a clean product baseline. Before editing loaded source/build artifacts, stop only the owned empty4121 development instance after checking its recorded PID/identity; retain its isolated data. Do not touch original4120 or the existing SnowLuma/AstrBot container.
- Build a smallest core-less local-host composition from the existing kernel/host code with both actual QQ factory registrations. Prove user-controlled reviewed source trust/preset and actual source/key/task cleanup; no Core, State SQLite or legacy local Agent starts.
- Prove a separate headless process survives GUI exit, attaches once on reopen and has a working local-only stop while the server is absent. This is not the existing parent-owned runtime worker, whose parent disconnect intentionally exits it.
- Prove real authenticated two-process closed control plus bounded credited bytes, then one claimed synthetic native send whose reply is deliberately lost. Hold the real reader/operation to distinguish cancellation from settlement. Reconcile the same-boot outcome read-only, then publish a new input: the original send remains once, but the remote-uncertainty hold does not poison the global sender. Prove a boot announcement alone cannot clear an unresolved physical hold.
- Add one small real two-stage upload→claimed-send proof: the raw private upload object stays local, the valid continuation publishes once, and another session/part cannot redeem it. Add a byte-custody cut after verified raw server staging but before codec/ASR; local loss no longer kills server processing, while server actor withdrawal still does. Do not expand G0 into the full32MiB/120s matrix.
- Build a minimal portable layout outside the checkout and verify all needed package/runtime/plugin paths resolve there. Verify the target runtime/dependency architecture; do not copy Linux binaries as a Windows build.

Pass evidence: a task-local report listing actual processes, kernel owners, byte hashes, zero local Core/State, exact repeat/cleanup outcomes and real package paths. An unresolved contradiction returns to design; it is not waived with generic RPC, forced trust or a text-only shortcut.

### G1 — Declare canonical contracts and stopped State migration

- Add one closed bridge/local-management contract and guards in `packages/contracts`, using existing limits/error/result vocabulary and distinct control/media/sensitive planes.
- Declare real authenticated host/source/task/material/claimed-attempt contexts and their private mapping; keep ephemeral native handles out of canonical intent fingerprints.
- Extend the State provider's private remote execution binding and same-attempt monotonic outcome enrichment. Preserve the absent-binding legacy service-local fingerprint.
- Add stopped full-root State format3→4 migration, preserving old IDs/fingerprints/receipt facts and existing older migration paths. New private metadata is not a local second State database.

Pass: boundary/oversize/forged-owner/mismatched-purpose guards; migration old IDs/timestamps/fingerprints and no historical execution; late evidence changes facts only and cannot start another effect.

### G2 — Independent local host and portable QQ native composition

- Add the independent host entry/profile lock and private same-user management discovery/attach/stop path. Reuse kernel config/trust/permissions/tasks/credentials and fixed native management, not another plugin hierarchy.
- Share the existing QQ native/source code at a maintainable package boundary; inject ports in the reviewed composition so both default-not-ready blockers are actually solved. Do not broaden arbitrary worker networking or activate forbidden local Agent roles.
- Implement local source settings/CAS, desired enable, actual plugin/native state, key target/version ownership and cleanup. Agent-link and platform secrets live with the daemon, not a GUI abort controller.
- Keep source and Agent-link status distinct, preserve local-only stop and prevent duplicate host/profile/native sources.

Pass: both protocol sources under the actual host/kernel; local trust/key/config withdrawal sticky; known postflight results retained; cleanup failures hold slots; GUI exit/return and server-offline stop meet A9.

### G3 — Server bridge registration and scoped ingress

- Add the authenticated selected-host/source management and upgrade at the existing service origin. V1 uses the existing owner bearer and states that trust model honestly; host IDs/serialized owners are not independent authentication or participant authority.
- Compose the server remote-source facade with explicit service-local/remote execution strategies. Absence of the selected local host is unavailable, never a fallback to server-held QQ credentials.
- Connect safe local input offers to the current controller/ingress/runtime authority and State dedup. Capture and track before SQL await; preserve account/native event identity across reconnection without replaying admissions.
- Keep local source trust/availability separate from server participant grants and already accepted cloud work.

Pass: both private/group protocols through real loopback bridge→actual State/Core; forged source/account/role/old Agent/boot/session rejected; wrong-instance/different target cannot inherit policy; scoped reads/quotas remain before LIMIT/admission.

### G4 — Real material custody, audio and cloud work

- Implement bounded local native material producers, credited remote streams, exact size/hash and the explicit raw staging custody cut before codec/ASR: complete all required parts' native readers and verified owned server staging under the original actor, then use that server actor/task lifetime without the old local source signal/check. Raw custody is not premature ready metadata.
- Preserve identity-less file observations and authorized later lookup, quoted notes, current materials, full-text documents, worker binary input and protected result artifacts.
- Extend direct/proactive media through a private candidate authority backed by the original actor/observation; do not relax a public origin kind into a grant.
- Keep server Magpie ASR/TTS/codec consumers and constraints, including six complete ASR spans and text acceptance before synthesis. No local Docker-codec requirement or fake transcription.

Pass: actual PNG/non-UTF8 file/WAV/SILK and real isolated worker results through both sides; corrupted/truncated/over-budget/permission-revoked streams fail; completed material/work survives local loss; proactive media is exercised instead of assumed.

### G5 — Durable once-only remote delivery

- Persist/freeze the exact remote execution target with the existing server plan/claim and passive quota/sequence reservation. A pre-existing/frozen delivery does not capture a replacement host/peer on retry.
- Execute with independent local source checks and bounded remote execution authority; keep upload-private continuations local and purpose/route/part/attempt/hash-bound.
- Separate platform publication, transfer/upload, acceptance, known postflight failure, transport loss and physical cleanup. The remote strategy must neither assume local cleanup settled in the sender catch nor set its permanent global cleanupFailure latch for mere remote uncertainty. Scope such holds to the original source/task claim and release only on matching actual cleanup/recovery evidence; unrelated sources and a new delivery after proven cleanup can continue. Server close joins its own resources and durably records unknown remote work.
- Reconcile retained outcomes only into the same claimed attempt. No new claim/send/voice gate, automatic outbox or replay after unknown/accepted/restart.

Pass: real controlled official multipart and OneBot stream/file-text publication; lost acknowledgment after accept sends once, late known receipt enriches only facts; source/host/account/key change cannot redeem old upload refs; native slot retained on failed cleanup; whole mandatory text precedes TTS.

### G6 — Desktop source management and existing personal surfaces

- Attach/start the independent host from the real production desktop entry. Expose distinct hide/quit-GUI/stop-host controls; a stop-host request cannot require a live server connection.
- Reuse QQ pure form modules and small components for local sources/keys. Keep local boot/config/key and server connection/assignment/policy CAS domains distinct.
- Preserve the existing Main personal HTTP/SSE/voice/speech controllers; the daemon's QQ connection is a separate purpose to the same Agent. Surface target mismatch rather than silently moving a local source.
- Retain server policy/judge/delivery Web management with an exact captured-root opener, labeled as server-owned. The existing factory-generated openWeb facade already works; do not fix the disproved missing-preload finding.

Pass: actual DOM and production Main/preload two-process actions: saved versus connected, key target changes, delayed old requests, GUI restart attaches existing host, offline local stop, correct source versus server policy writes; personal profile/facts/tasks/artifact/voice/speech regressions remain intact.

### G7 — Versioned local package and integrated acceptance

- Produce the Windows-x64 portable preview with runtime, production dependencies, reviewed plugins, GUI/host entries, launcher and version/protocol stamps. No tokens, user profiles, model assets or SnowLuma binaries enter it.
- Exercise the package from a fresh independent path/profile, not the workspace. Record actual Linux native evidence and distinguish a statically verified Windows candidate from Windows-device execution if no such runner is available.
- Run full relevant workspace types/packages/QA/lint/format/build and complete controlled two-process/native probes. Independently review cross-layer source/authority/material/effect/lifecycle/UI coverage.
- Update canonical backend/frontend contracts and operator/start/stop/local↔server setup guidance once, then link evidence from the task. Real user QQ/model/Windows-device trial is a later explicit scope.
- Present exact local work-commit batches once for approval; work commits precede this child archive and its work-hash journal. Do not push/publish/amend or archive unrelated tasks.

Pass: all L1–L11 / A1–A10 mapped to evidence, no known blocking finding, usable versioned local handoff with accurate OS limits, final task manifests/links clean and local-host placement actually exercised.

## Validation commands and rollback points

The existing full-workspace gates remain:

```sh
pnpm -r typecheck
pnpm -r test
pnpm test:qa
pnpm lint
pnpm format:check
pnpm build
```

Run the existing Docker opt-in suite with the explicitly prepared worker image, and the G0-added controlled host/bridge/native/package probe entries documented with their actual reports. New probe/script names are declared by implementation once; this planning document does not pretend they already exist.

Source/controller edits must not widen kernel readiness or source trust merely to pass these commands. Stop/join only owned test processes/containers and verify their real identities before cleanup. Package/native runs use fresh profiles outside original data.

State4 rollback is a stopped full-root restore to an independent reviewed backup, not an in-place schema downgrade or a replay of old unknown effects. Local host upgrades require actual old-host/source settlement before a replacement instance; an incompatible running host is diagnosed, not force-killed or silently duplicated. Keep versioned build outputs and source evidence for the handoff; no automatic OS service/public-release action belongs here.

## Work allocation after G0/G1 stabilize

Parent owns canonical contracts, process/network composition seams and integration order. Separate bounded ownership can cover local native sources/daemon, server authority/State, media/work and delivery, and DeepSeek-owned desktop forms/UX. Interfaces freeze before parallel edits; overlapping lifecycle/source changes stay sequential. Reviewers inspect real effects and task/stream ownership, not only returned test counts.

Subagents read the compact task/spec manifests first and follow only their relevant research/source links. Each reports changed paths, exact tests/evidence, unresolved concerns and physical cleanup. No agent starts live QQ/model tests or edits another workstream's files to make a fixture pass.
