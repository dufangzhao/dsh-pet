# Shared desktop backend review

Read-only source review after backend handoff; frontend/build were not frozen. Findings below describe source traces, not observed native test failures. No services, Electron, browser, Docker jobs or project gates were run for this review. The parent received the findings as they were identified; file lines describe the inspected revision and may move during fixes.

## Findings

1. **A detached old SSE check can retire a new connection.** [Controller:456](../../../../apps/desktop/src/main/companion-client-controller.ts#L456) starts an untracked `host.isCurrent(oldSource)` promise for each event. After a new target is connected under the same plugin owner/generation, a delayed `false` calls `retireSource(oldOwner)`; [retireSource:672](../../../../apps/desktop/src/main/companion-client-controller.ts#L672) compares only source owner, so it also matches and aborts the new connection. Regression: hold old event's authority check, retire and reconnect to a new endpoint with the same source owner, then resolve old check false; new connection and state must survive. Fence the callback against the exact connection after the await. The separate `#run` catch path is tracked by `connection.work` and was not established to have this replacement race.

2. **An entered rename can commit while the original save reports stale.** [Artifact:64](../../../../apps/desktop/src/main/companion-artifact.ts#L64) checks current, then awaits `rename` and returns `saved`. If retirement aborts after rename starts but before it settles, [host adapter:144](../../../../apps/desktop/src/main/companion-client-host.ts#L144) rejects the physical success due to abort and [controller:214](../../../../apps/desktop/src/main/companion-client-controller.ts#L214) also fences the result. A real final file is therefore saved while the original operation reports stale, contrary to the committed-file outcome contract. Regression: gate an entered rename, retire, let it commit and check the original operation reports its real saved fact without applying it to the new target. Existing [artifact tests](../../../../apps/desktop/src/main/companion-artifact.test.ts) cover chooser retirement and aborted stream, not this commit race.

3. **Committed endpoint changes can be reported as uncommitted failures.** [Host adapter:64](../../../../apps/desktop/src/main/companion-client-host.ts#L64) commits `configs.save`, then returns the result of a second fallible `readSource`. If source disable/revoke occurs in between, [connect:260](../../../../apps/desktop/src/main/companion-client-controller.ts#L260) returns that failure immediately even though Config changed and the observer has retired the old binding. Public endpoint/revision may remain stale because observer reinitialization is skipped while connect holds control. Regression: gate the post-CAS source read, revoke after the commit, and require the committed endpoint/revision and unavailable/retiring state to be reported. A stale CAS must still preserve the old connection.

4. **The disabled-role ledger records unrelated unavailable roles as deliberate user choices.** [Main:336](../../../../apps/desktop/src/main/index.ts#L336) records the ledger for any outer successful plugin action Result, including one carrying `operationError`. [Ledger:35](../../../../apps/desktop/src/main/shared-application-state.ts#L35) adds every known role whose `desiredActive` is false. Entries start with desired=false in [PluginManager:182](../../../../packages/host-kernel/src/runtime/plugin-manager.ts#L182), including roles startup skipped as rejected or not admitted at [Main:237](../../../../apps/desktop/src/main/index.ts#L237). One unrelated or failed action can therefore persist such a role in the disabled list; subsequent startups skip it even after its admission problem is fixed. Regression: execute an unrelated successful action and a failed action with a skipped role present, then prove the role has not gained a disabled marker; explicit successful disable/enable must still persist.

5. **A token containing JSON-escaped characters can be echoed into public DTOs.** The controller accepts a token containing `"` or `\\` at [controller:255](../../../../apps/desktop/src/main/companion-client-controller.ts#L255). [Host adapter:152](../../../../apps/desktop/src/main/companion-client-host.ts#L152) scans `JSON.stringify(value)` for known secret patterns. JSON adds escape characters, while [redactor:17](../../../../packages/host-kernel/src/credentials/redactor.ts#L17) registers the raw, URI-encoded and base64 forms; a decoded returned string equal to such a token can bypass this check. The existing [KnownSecretBoundary:18](../../../../packages/host-kernel/src/credentials/secret-boundary.ts#L18) checks decoded string values and keys. Regression: a valid 24+ byte quote/backslash token echoed in a snapshot or profile must never appear in the returned state.

6. **A stop receipt can confirm the wrong target.** [Protocol:184](../../../../plugins/text-client/src/client/protocol.ts#L184) matches commandId only. [stopTask:210](../../../../plugins/text-client/src/client/protocol.ts#L210) does not check receipt.taskId against the requested task; [controller:511](../../../../apps/desktop/src/main/companion-client-controller.ts#L511) treats the malformed receipt as accepted. The actual service records the requested ID at [runtime:621](../../../../packages/companion-runtime/src/runtime.ts#L621). Regression: return matching commandId but different/null taskId and require an uncertain outcome with the same retry ID, not confirmed selected-stop success.

7. **A pending intent can be resurrected after its confirmed snapshot.** [Controller:373](../../../../apps/desktop/src/main/companion-client-controller.ts#L373) removes pending messages on matching `inputId` and pending stops on terminal task. If the corresponding HTTP command response settles later, [command:509](../../../../apps/desktop/src/main/companion-client-controller.ts#L509) unconditionally re-adds the pending entry. A dropped receipt can leave a confirmed message labeled uncertain indefinitely because failure schedules no refresh; a terminal stop can similarly remain pending. Regression: deliver and adopt the confirming snapshot before releasing/dropping the command response, then assert the pending record stays cleared.

8. **Task detail is not correlated to its requested ID.** [Protocol:340](../../../../plugins/text-client/src/client/protocol.ts#L340) accepts any parsed task for `GET /api/tasks/<id>`; [controller:585](../../../../apps/desktop/src/main/companion-client-controller.ts#L585) caches it by returned ID. [saveArtifact:635](../../../../apps/desktop/src/main/companion-client-controller.ts#L635) admits artifacts in that cache, so a damaged/misrouted detail response can show a different task and allow its artifact. Regression: return a valid task B for requested task A, and require failure without caching B or authorizing its artifacts; check artifact-to-task correlation as well.

9. **An already-aborted source can be installed as a stuck connecting binding.** [Host adapter:35](../../../../apps/desktop/src/main/companion-client-host.ts#L35) captures a source signal before async trust verification and endpoint reads, then returns it without a final abort/current check. If disabled during those awaits, [connect:273](../../../../apps/desktop/src/main/companion-client-controller.ts#L273) can attach an abort listener to an already-aborted signal (which does not replay the event) and publish `source:'ready', phase:'connecting'`. `#current` is false, so refresh cannot move the projection. Regression: hold the final source read, disable the source before returning, and require an unavailable/disabled state rather than a stuck connection; revalidate after async reads and at listener installation.

## Reviewed boundaries and limits

- The inspected source uses a real actual-platform `DesktopHost`, source-specific RuntimeSession stop wrapper, Config CAS, permission leases, fixed sender/file-URL validation and fixed preload method table. Shared startup excludes the named legacy roles through the host admission check. Those observations are source review, not evidence that the native gate passed.
- JSON response reading has an explicit 64 KiB bound, Main state an 80 KiB aggregate bound, and profile is separately bounded. Existing controller tests include a near-64 KiB snapshot case. A full native boundary, lifetime and Windows integration run remains pending; no Windows absence was classified as a product failure.
- Inspect the final integrated changes again after backend fixes. Do not count unit/fixture source inspection as proof of physical network drain, OS chooser behavior or Windows functionality.
