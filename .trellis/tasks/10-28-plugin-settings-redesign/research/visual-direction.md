# Selected pet-first visual direction

Use the DeepSeek max frontend-design.md v2 as the visual research, with this coordinator reconciliation and the revised PRD/design as the actual scope. Cortico contract evidence is in cortico-reuse.md. No product implementation is claimed.

## Preserved visual system

Keep five existing ui-kit role colors and light/dark variants,236px quiet sidebar, content capped1120px,40px ordinary gutters, clear label/value tracks and original ledge-style preview. Segoe UI/Microsoft YaHei with explicit inheritance for all Chinese prose/form controls; no remote fonts. Title26px, section16px, labels14px, hints13px/min12px with1.6 Chinese line-height. No marketing hero, provider-logo wall or copy of Coopanion character/branding/dotted stage. Review1040x740 and760x560 native layouts and all themes.

## Correct product structure

Start configures actual providers/model/keys and shared pet preview. Persona (人设) replaces Habits and contains names/reply language/style plus the whole editable persona prompt and effective-prefix preview. Appearance selects at least two actual original shapes and four palettes, with the same native/preview values. Conversation is the ordered overview of the same everyday pet interactions, including actual messages/actions/reactions and guide/update notices. Voice owns current recognition/readiness, applicable input controls and send-after-recognition. Extensions/About remain quiet recovery entries.

The desktop pet is the primary human interface. A bubble contains the question/explanation AND actionable choices/text or masked secret input. A choice directly validates/saves through the common backend and then both bubble and Settings show the committed result. Do not make clicking a bubble merely navigate to a Settings row. Settings is a same-state secondary editor; long-form prompt editing can expand there. The guide has actual dynamic steps, skip/later/retry and resumable host state, not a second front-end-only progress model.

## Required corrections to illustrative research

- No-Key users can complete local application guidance and physical pet interaction. Explicit offline scripted experience remains labeled; no paid model connection or AI response is fabricated.
- Names/persona/prompt text keep drafts and explicit Save on errors/conflicts. Choices may save directly with actual acknowledgment. autoSend has its authoritative editing location on Voice.
- Cortico safe-boundary prefix reload means saved, pending and applied are distinct. The editor may not label an unsafely pending revision as immediately active. Show full actual prefix sections, with editable persona text and clearly marked computed environment/tool segments; no hidden second personality.
- Reply language does not promise a complete UI localization system in this iteration. The recording limit comes from the host, currently20 seconds. No42/60-second examples, fake reminder success, automatic model download or unavailable connection-test controls.
- The interaction timeline uses clear user/pet/action/application labels, readable time and non-color-only status. A poke row and a blush-applied row describe verified facts, not an inferred feeling. Persisted cursors/replay do not cause old actions to execute again.
- Preview remains usable while the desktop character is hidden. Optional page disablement does not pretend to disable an unrelated ASR/provider or erase the character preferences. Preserve tested native outer geometry unless deliberately updated and verified.
- Update notices use actual available/downloading/ready/failed/completed stages. Use local fixture data only in acceptance mode; do not show nonexistent real release versions/progress. Bubble later/retry/restart actions are actual bound operations, not model-generated arbitrary URLs.
- Missing required persona/action consumers are unfinished work, not grounds to silently ship an empty page and call it complete. Normal UI has no schema/JSON/revision/owner/lease/hash/runtime/task/channel controls, raw tool JSON or internal framework pages.

## Pet interaction states

Use one clearly visible active choice prompt, normal speech and a compact recording/stop/cancel strip. The original pet shows actual state/expression, and an action receipt supplies the history event. Queued nonurgent update notices wait while a setup/permission choice is active; tray/settings recover if the pet is hidden. No toast/overlay covers essential input or actions. Respect keyboard focus and reduced motion.
