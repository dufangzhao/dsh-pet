# Cortico reuse boundary after R9/R10

Read-only research, 2026-10-28. Target: Cortico **0.2.7**, commit **cb9ddbd685bcccba1f29905098648f46a79b3862**; the parent verified this is Coopanion 0.2.10's reference and its local vendor is uninitialized. This recommendation supersedes the standalone page-protocol and bespoke conversation-loop portions of [plugin-contracts.md](plugin-contracts.md).

## Decision

Reuse Cortico Core as the **single agent/session/event/tool loop**, its Persona/World/ResponseClient interfaces, and its existing WebUI page/panel declaration and manifest protocol. Retain the desktop host as the **single installation, owner lifecycle, config CAS, OS permission and encrypted-secret authority**. Adapt these boundaries; do not run Cortico's stock launcher/deployment writer/extension installer beside the current host. The pet bubble and Settings are two views/controllers of the same interaction, not two conversations. This iteration should deliver a usable Core-powered scripted-provider event/tool/reply round-trip with desktop/config tools, not stop at interface sketches; it must not retain a parallel DemoController agent loop.

| Reuse | Minimum desktop responsibility | Pinned evidence |
| --- | --- | --- |
| Core | Construct one Core with a host projection of LoadedConfig and one supervised lifetime; retire DemoController's reply/session orchestration after migration. Keep its working capture/ASR/media adapters as input services. | [Core:57–195][core], [Core overview][core-doc] |
| Persona | Implement one small DesktopPersona: exact full prompt segments, one persistent receivesEvents session, tool selection, simple handoff policy. This is product semantics, not a new agent loop. | [Persona contract][personas], [types:994–1059][types] |
| World | One desktop interaction World supplies genuine pet/user/application events and authorized action tools. Map an enabled ordinary plugin's World role into Core.mountWorld/unmountWorld under the current owner's signal. Page-only contributors need not invent a fake agent World. | [World contract][worlds], [Core:629–671][core] |
| Memory | Reuse Core event/session/transcript/blob persistence; Persona owns semantic Memory and BlobStore. Memory is optional opaque object + memoryDir, not a mandated database or a second configuration source. Start with the minimum persona memory policy; do not import Soulmate dreams/QQ/Minecraft machinery. | [types:1029–1049][types], [Persona examples][personas] |
| Provider | Reuse ResponseClient.respond(Request, GenerateOptions) → Generation and ProviderModule metadata/transport contracts. The desktop adapter binds actual provider owner, model, cancellation, permissions and broker use. | [generation:66–88][generation], [provider base:17–141][provider] |

CoreDeps.llm is an injection seam, **not a total provider-registry bypass**: Core still constructs ProviderRegistry and reads providers/activeProvider/spec and model facts. Registry has a top-level await that scans/imports provider directories; activeSpec and context estimation still use module metadata ([Core:139–179, 283–307, 430–451][core], [registry:12–38][registry]). Populate a non-secret current-provider projection and admit only the required modules. The present text/context → text demo respond capability cannot represent tool calls, structured Response items, attempts or stream cancellation: adapt the full Cortico protocol at the provider boundary, rather than run another outer agent loop around that method. DeepSeek Chat Completions is not automatically compatible with Cortico's default /responses provider ([provider docs][providers]).

## Existing pages/panels replace the proposed new UI protocol

Cortico already exports WebUiPageContribution(id/kind/label/config/panels/promptDocs/storage/invoke/stream) and serializable WebUiPageManifest. Page IDs are namespaced world:/persona:/memory:/llm:, panel IDs are local. Generic config needs no browser code; builtin panels also need no plugin bundle ([protocol:31–35, 187–289][protocol]). Reuse these shapes instead of a second console-page view DSL or a builtin-only view enum.

The local extension is an ownership adapter, conceptually **{ owner: OwnerRef, contribution: WebUiPageContribution }**, with host-owned ordering/visibility and the existing declared registration transaction. Callbacks/local paths stay server-side; only the upstream public manifest projection crosses IPC. Map page/panel requests to that registered current owner and declared methods. Generic own-config forms and an audited host command panel invoking existing declared commands give an unknown fixture a usable page without editing shell navigation.

WebUiPanelContext already supplies root/signal/invoke/stream/setConfig/own/interval/frame/guardLeave and mount → Disposable cleanup ([panel:39–127, 593–603][panel]). Reuse the contract for audited application panels. It is a scoping convention, **not a sandbox for hostile browser JS**: continue forbidding arbitrary untrusted scripts/DOM in the privileged console; external pages can use declarative config plus authorized host-rendered commands. Do not scrape or depend on Cortico's current HTML/DOM/client component internals; the docs explicitly reserve them as developer UI, not a downstream-stable interface ([WebUI public boundary][webui]). A complete stock WebApp/HTTP server is unnecessary when the existing Electron IPC can adapt these contracts.

Keep the accepted single-layer Pet manifest/PluginManager as deployment identity/trust authority. Cortico world/provider/bot metadata describes integration roles; do not introduce another independent three-kind npm manager, automatically import installed extensions, or let WorldAssembly persist enabled state in parallel. Upstream WorldAssembly constructs even inactive definitions, and stock installer can approve dependency build scripts: neither is the current source-approval gate ([extensions][extensions], [WorldContext/Assembly][world-source]). Explicit source-approved imports/adapters are required; automatic compatibility with all Cortico npm extensions is not claimed. PluginManager alone decides install/trust/enable/disable/remove; Core mount/unmount is its delegated World runtime operation. Core may report runtime facts/failure but cannot independently re-enable or persist a competing plugin decision.

Cortico availability=inactive may still expose pre-activation configuration, and Persona pages are normally always active; those states are not the desktop plugin lifecycle. Filter primary pages by the current host owner's registration/lifecycle. Keep host management/recovery reachable, retain build-pinned application-page admission and saved disable/removal choices, and publish lifecycle onChanged for async faults/unmounts. Core unmount returns stop failures while removing its World; translate failures into the host's honest cleanup/pending_restart result instead of reporting a successful uninstall ([protocol:274–301][protocol], [Core:649–671][core]).

## One interaction history and one live session

~~~text
pet text / voice transcript / poke / completed drag / guide choice / applied reaction
  -> authenticated DesktopWorld ingress -> Core WorldHost.pushEvent
  -> Core event store(cursor) + selected delivery -> the one persistent session
  -> ResponseClient + World tools -> outputTap -> pet bubble AND Settings projection
  -> actual presentation/action receipt -> same Core event store(archive-only when appropriate)
~~~

EventEnvelope already has globally increasing cursor across runs, source/type/ts/origin/tags/meta and attachments. WorldHost.pushEvent supports deliver:false and flush/debounce/piggyback/preempt/interrupt ([types:30–69, 604–626, 679–720][types], [events:1–5, 203–220][events]). Use semantic events such as pet.message, pet.touch, pet.drag-completed, pet.reaction-applied, app.guide-choice, app.config-result and app.update-notice. Do not log mouse-move samples. Append a reaction-applied event only after the real renderer/window action acknowledges success; an intention is not a blush that happened. Credentials never enter event text, meta, tool arguments or transcripts.

Use the Core event store as the cursor-ordered everyday-history projection, including presented assistant/application notices as correlated archive-only events, with references to the native Core transcript/run/response/tool call. This is one projection over Cortico's own records, not a second chat database. outputTap carries transient partial output; finalize/ack one visible message event with a stable response/event identity. Record cancellation/failed or partial presentation truthfully. Correlate and deduplicate replay from native records so assistant output is not shown once from transcript and again from its receipt. Reconnect queries events after the last confirmed cursor and rebuilds the projection; never execute historical guide choices/tools again.

Cortico transcript retains appended session items and handoff/clear/prefix-reload boundaries, while session-main is rewritten for context; it is not a second user conversation ([transcript:1–35][transcript], [Core:126–131][core]). **Do not assume every archived event is also in transcript or that transcript has the event cursor.** Transcript writes currently swallow append failures; event append mutates in-memory cursor/list before disk append. Catch/report failed ingress/receipts and do not claim crash-atomic durability from these APIs ([transcript:78–84][transcript], [events:203–215][events]). ClearSession resets context and leaves native archives; history-clear UI must state/implement its actual archive-retention/deletion policy.

WebUiPageContribution.stream explicitly supplies **no replay cursor/backpressure or disconnected-frame replay** ([protocol:267–270][protocol]). Add cursor-based reads/reconnect in the desktop projection; a panel stream notification alone is not reliable history. Subscribe once per Core lifetime and fan out to current owner/page listeners: event-store onAppend returns void with no unsubscribe ([events:218–220][events]), so repeated page mounts must not register immortal Core listeners. Page unmount drops its subscription, not the Core session or microphone capture.

Before a paid model/key is configured, the same bubble runs an audited local first-run/configuration guide with actionable options. It uses the same management service, emits safe guide/config/update facts into Core storage with deliver:false, and renders deterministic notices; no model call is needed to ask for a provider/key. User text/voice can use the scripted ResponseClient until a genuinely permitted provider is ready. Secret inputs go straight to the existing human credential route/broker; history contains only a value-free completion/failure notice. No published source/installer channel is presently established: update UI must read a truthful host status adapter and may demonstrate the bubble notice/action/result path with an explicit fixture; do not invent a live update service, version or download. Update notices do not install code. Model prompts cannot grant trust or approve permissions.

## Full editable prompt and actual application

Persona.systemSegments returns ordered text that Core concatenates verbatim; PrefixSegment.sourceKey links editable documents, and sessionHead is a separate nonpersistent computed head ([types:954–959, 994–1043][types]). Store the **entire editable persona prompt**, not only a style/preset label, in the canonical revisioned desktop profile. Name/address/language/style must have explicit visible semantics in that prompt/segment projection; do not append an undisclosed hardcoded personality after the editor. Show the complete effective prefix preview, including clearly identified World/tool environment segments, so “full prompt” is not an unrelated textarea.

Keep an editable UI draft on errors/conflicts. On exact owner/schema/revision-checked save, update the non-secret runtime projection and request **core.loop.reloadSystemPrefix()**, await its safe-boundary result, then report applied revision. It preserves user/assistant/tool records and records a prefix-reload boundary; an in-flight batch finishes before replacement ([loop:1756–1802][loop]). Expose saved vs applied revision/pending/failure; successful CAS is not proof a running request used the new prompt. With no running session, apply on the next initialization. Test the actual ResponseClient request's system text after reload. Upstream waits for the whole current batch, not necessarily the next request within that batch: to promise literal next-request application, use Cortico interruption/drain plus serialized reload before resuming generation; otherwise show pending and guarantee the next request after the applied acknowledgment, not an already-running batch.

Cortico promptDocs and public GET/POST /api/prompts(baseRevision), prefix preview/reload contracts are reusable UI semantics ([WebUI routes][webui]); their stock persistence is file/override based. **Do not write both promptDocs files and desktop config as independent sources.** For this product, adapt read/save/preview/reload to the same profile CAS. Import existing templates once if needed; generated file views, if required by a selected upstream template implementation, are disposable projections. The desktop schema/value budget must intentionally accommodate the supported full prompt and reject oversize input without truncation (current [schema.ts:207](../../../../packages/host-kernel/src/config/schema.ts#L207) caps string bounds at 4096).

## Authority and migration: keep one owner for each decision

| Authority | Keep canonical | Cortico adaptation |
| --- | --- | --- |
| Settings / prompt / appearance / provider selection | Existing ConfigService + FileConfigStore CAS and stable plugin/instance keys | LoadedConfig.config and ConfigGroup dotted paths are **runtime/UI projections** of committed records. Translate declared group/field IDs to exact owned config fields. setConfig cannot skip schemaVersion/expectedRevision or cross owner boundaries. Cortico schema coercion ignores unknown values; retain strict host validation ([config:166–184][config], [group schema:47–61, 131][groups]). |
| Secrets and network/native effects | Existing encrypted broker, task/owner-bound permission leases and approved capability providers | Stock LoadedConfig.secret / WorldContext.secret / storeSecret and provider .env are not adopted. Inject the full ResponseClient adapter whose authorized operation uses withSecret, and never put plaintext into long-lived Core config/env or cached UI/provider state ([WorldContext:29–47][world-source], [registry:81–109][registry]). |
| Plugin trust/enable/remove/restore | Existing PluginManager, source digests, builtin ledger, generation checks, cleanup and TaskSupervisor | World/page mount follows host activation; unmount/fault revokes bound facades/tools and listeners. Cortico's WorldHost lease is useful secondary cleanup, not a replacement for current OwnerRef or successful external-resource verification. |
| Future model management | Existing proposed discover/read/validate/change service with exact target/action and schema/revision, immutable reviewed intent | A thin World ToolDef calls that scoped service under the real supervised owner/task. Tool names/tags and Cortico extension self-description are not authorization; ordinary capability-use cannot grant blanket management. No raw broker/manager, self-approval, trust/preset mutation or installation tools. |
| Everyday session/history | One Cortico Core event/session/transcript data directory under existing plugin-data ownership | One-time import old DemoHistory messages with stable legacy IDs; retain the original as read-only recovery until cutover succeeds. Stop old history writes/old agent loop after cutover; both windows read the same new projection. No permanent dual writer or unrelated DB. |

## Distribution and changes to the previous proposal

[LICENSE][license] and [package:2–15][package] confirm MIT / 0.2.7 / Node >=22. The root manifest is private and includes canvas, mineflayer, mineflayer-pathfinder, prismarine-viewer and vec3; **do not install the Git repository root's dependency graph as the desktop runtime**.

[publish-package:17–30, 67–90][publish] creates an ESM package with public **./* → ./src/** subpath exports: imports such as **cortico/core/core.ts**, cortico/core/types.ts, cortico/core/generation.ts and cortico/web/shared/webui-protocol.ts are supported. There is no root entry to guess as src/index.ts. Published dependencies are express, fflate, react, react-dom, react-textarea-autosize, tar-stream, ws plus @types/express, @types/react, @types/react-dom, @types/tar-stream, @types/ws. They cover the advertised extension closure; type packages are not all actual Core runtime imports.

The publisher still copies **all src** into the package ([publish:164–170][publish]); a short dependency list is not proof of a core-only artifact. Select only required World/provider source/assets in desktop packaging, preserve MIT notices and pinned provenance, and never use the stock launcher that imports all builtin Worlds. The docs explicitly support downstream World selection ([World loading][worlds]). Verify the pinned release/package artifact and its closure; no package was downloaded/packed/installed in this research.

Core source has filesystem-relative provider discovery, .ts ESM and top-level await. The local [build.mjs:30](../../../../apps/desktop/build.mjs#L30) currently bundles the runtime worker as CJS (target node24), while main is ESM. Use a downstream-compiled ESM agent bundle/process, or an external ESM setup with an explicitly verified TS loader/runtime and required directory layout: the published subpaths point to TypeScript source, not precompiled JavaScript, and Node >=22 alone does not prove those imports execute from node_modules. Do not statically bundle Core into CJS and assume the injected client erases these issues. Actual Electron runtime versions, path/ASAR behavior and shutdown remain acceptance probes.

**Withdraw:** the new standalone console-page view DSL and proposed page-command RPC (reuse upstream panel invoke/stream over the existing transport), a second browser-panel lifecycle implementation where upstream contracts suffice, separate text/voice-only history, and any new custom model/tool/context loop. **Keep:** host owner wrapper and registration gating, async onChanged, safe route fallback, pinned application-UI bootstrap/disabled-choice ledger, strict config CAS/migrations, credential separation, target/action management authorization, actual preference consumers, global recording scope and controlled DOM boundary. Adapt the fixture/page tests to Cortico's contracts rather than preserve the earlier type names.

## Unmeasured gates

Read-only source review only: no task start, code changes, vendor initialization, installs, builds, provider charges or runtime tests. Before claiming integration complete, verify: (1) pinned minimal ESM artifact on real Electron; (2) scripted ResponseClient event → tool → result → reply/abort round-trip; (3) poke/applied blush/chat/guide/update in one cursor history with reconnect/restart/import dedup; (4) full prompt CAS/conflict + prefix reload changes actual request without losing history; (5) async plugin withdrawal/cleanup, exact reviewed management authority and secret exclusion from tool/event/transcript/log output. Upstream protocol reuse does not itself prove these desktop behaviors.
