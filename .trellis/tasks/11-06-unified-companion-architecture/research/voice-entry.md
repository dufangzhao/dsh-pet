# Shared voice entry: source-backed next-stage research

Read-only, 2026-11-09. Only this report is written; no child/task activation, product/spec change, build, install, model/service/device call or original trial-data inspection. Source inspection and public text fetches are evidence of interfaces, not working speech, hardware or latency.

## Direction and recommended first child

**[R22](../prd.md#L33) supersedes the earlier provider alternatives: all models, including ASR/TTS, enter through Magpie.** Local device capture/playback remain local mechanisms; this approved path does not call local ASR/system-TTS models or third-party model endpoints directly. Legacy plugin inventory below is reuse evidence, not a competing model route.

[R3/R8](../prd.md#L13) retain responsive full-duplex and useful multimodel roles; [R11–R20](../prd.md#L21), [ADR-0015](../../../../docs/adr/0015-independent-continuous-agent-runtime.md#L15) and [ADR-0016](../../../../docs/adr/0016-cloud-service-and-pluggable-features.md#L13) require one independent Agent, removable features, text-first progression and continuing independent work. Voice must enter that same service, not restore the old local Core.

Recommend **shared explicit utterance input** first: record a bounded utterance from web/desktop, transcribe through an ordinary **Magpie-backed ASR provider**, submit the final text through the existing message command, and display the continuing Agent's normal reply.
Reuse capture code; keep text/identity/persona/memory/work canonical.
This is an ordered increment toward R3, not a rejection of duplex or a claim that push-to-talk implements it.

A screen record/finish/cancel control is the smallest portable entry; reuse press/toggle gesture rules if desired, without promising Windows global hooks on Linux/web.
Do not disable recording merely because the Agent is thinking: [runtime interaction](../../../../packages/companion-runtime/src/runtime.ts#L641) permits busy input, delivered at supported steps, while unavailable/quiescing sources remain explicit refusals.
A particular recognizer can still be busy; that is a provider resource limit, not a global thinking rule.

Normal finish may send the final transcript once under an explicit autoSend setting; an editable draft/review mode can coexist.
Recommend preserving fluid direct input rather than imposing confirmation on every utterance.
The old autoSend=true is a [legacy default](../../../../plugins/voice-chat/plugin.json#L71), not proof of a new composition/user preference.
Draft-first, single-device automatic speech and audio retention choices remain recommendations, not inherited user decisions; see the final decision section.

- Legacy local ASR needs pinned resources/native bindings and SAPI is Windows-only; no cache/model/device availability was probed. Under R22 these are historical implementation facts, not a proposed direct-model route. The new ASR/TTS path needs actual Magpie audio model/format/authorization metadata; none is inferred from text connectivity.

## Minimal new seams, with ordered scope

1. **Neutral capture package and fixed client control.** Reuse renderer/worklet implementation behind a shared capture ticket/callback type, separate from DemoSnapshot/history. Desktop fixed Main/preload methods bind capture intent, current connection/agent, frame, selected provider/revision and epoch; web owns its local browser tracks under browser permission. Main is the desktop authority owner, not the sampling thread.
2. **One bounded Magpie transcription plane.** Use a service-hosted ordinary Magpie ASR provider for web + current Linux desktop parity, initially with controlled peers. Narrowly implement missing media/network/credential composition. Gateway backend placement is Magpie's responsibility; project clients do not bypass it to execute another ASR model.
3. **Final text → existing Agent.** Normal finish runs ASR; only final accepted text can submit one ordinary message command. Reuse same commandId on an unknown retry, with immutable final payload/current target; a revised transcript is a new intent. Partial hypotheses remain ephemeral and never independently trigger memory/tools. Do not add an Agent/Session or second transcript database.
4. **Output increment separately.** Manual read of a selected committed reply can precede automatic new-reply TTS. Reuse current pet player/settings mechanics where lawful; synthesis comes from the Magpie audio adapter and web gets an explicit local output owner. No history-on-connect/reconnect replay, duplicate speech across clients or automatic public posting. These are proposed delivery policies, not facts already chosen by the user.

New wire/control design must distinguish capture intent/ticket, ASR task, transcript-final result, message command/receipt, utterance/playback and selected logical work. It needs explicit formats/limits/sequence/end/cancel, provider/source generation and captured target ownership. Existing media owner/task references are host-derived; browser headers are not authority. Exact new method/route names belong to the child contract, not this research.

No new state database/migration is intrinsically needed for transient audio and normal text acceptance. A modality/provenance extension, if required in canonical messages, is additive typed JSON in the existing owner, not inference from command-id prefixes. Current message requests are closed: do not invent a voice flag that the actual API does not accept. Raw-audio retention is not silently approved by a successful text submission.

## Media, cancellation and concurrency

[Capture ticket](../../../../packages/contracts/src/demo.ts#L106) and [ASR limits](../../../../packages/contracts/src/local-asr.ts#L70) use16kHz mono Float32,1600 samples/6400 bytes per100ms frame, max20s/320000 samples. Full input is1,280,000 bytes; WAV conversion uses16-bit mono. Actual AudioContext sample-rate mismatch is currently an explicit format error, not an invented resampler success.

[Media contracts](../../../../packages/contracts/src/media.ts#L14) allow256KiB chunks,8 unacknowledged chunks and2MiB buffering per stream; [TaskMediaPeer](../../../../packages/host-kernel/src/tasks/media-peer.ts#L75) checks owner/task lifetime, credits and cancellation. These are a reusable transport, not an already exposed browser-to-service protocol. Audio must not enter control-plane JSON/IPC as arrays/base64, SSE snapshots or an enlarged global JSON parser; provider-required native encoding belongs inside its bounded audio codec, and keep64KiB JSON/80KiB Main projection and a separate bounded binary HTTP/media plane.

Capture, recognition, model activity and playback are independent channels. Permit capture while model/work runs when capture/provider resources allow; do not copy DemoPhase as a global mutex. Existing local recognizer has one work slot; cancellation/resource busy must remain specific and visible. Do not add a new scheduler to hide missing concurrency.

| Control | Required meaning |
| --- | --- |
| Finish capture | Stop tracks, flush/ack tail once, finalize ASR; submit or draft according to the explicitly chosen mode. |
| Cancel capture/ASR | Revoke that intent, release device/bytes/task, ignore late results; never auto-submit a discarded partial. |
| Stop playback | Immediately stop local player/queue and revoke playback epoch; not a selected-work or model stop receipt. |
| Stop foreground | Existing service endpoint fences/drains current generation; preserves independent accepted work. |
| Stop selected work | Existing taskId/commandId path; cancel-requested is not physical termination. |

Retarget/disconnect/source withdrawal must cancel the bound audio pipeline and join actual source/media work before replacement; late permission, ASR, bytes and playback callbacks recheck captured identities. Cancel after a message was accepted cannot erase that canonical message or silently cancel its tasks. No reflex/explicit stop waits for a classifier. New text/voice input uses the existing next-step input semantics; automatic foreground interruption on mic start is not established policy.

Current [speech contract](../../../../packages/contracts/src/speech-output.ts#L13) caps utterances4000 code points,queue4 and PCM2MiB, normally24kHz. [Renderer playback](../../../../apps/desktop/src/renderer/speech-output/playback.ts#L93) waits for the complete utterance before source.start, even though providers use media chunks. Encoded Magpie mp3/SSE requires an actual decoder/adapter; no format relabeling. Started/ended receipts prove player lifecycle, not that a human heard samples; played-prefix timing/lip-sync/truncation remain work for a later streaming/output slice.

## Browser, platform and verification boundaries

[MDN secure-context source](https://raw.githubusercontent.com/mdn/content/main/files/en-us/web/security/defenses/secure_contexts/index.md) distinguishes HTTPS/loopback/file from ordinary HTTP origins. [getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia) requires secure context and permission; LAN HTTP text access does not provide microphone access. Remote HTTPS must also avoid mixed-content media APIs. Embedded pages need microphone Permissions Policy; no insecure-origin flag is a shipping solution.

[Web Audio autoplay policy](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay) is separate: audio playback/resume may require user interaction or site policy and can be blocked. An explicit record/enable-sound control is sensible, not proof permission was granted. Electron file context does not bypass Main's current denial or the kernel lease; exact loaded-frame/device grants need native acceptance. Do not use automatic-consent flags as authorization evidence.

Measure capture-finalization→transcript→message acceptance→reply separately; later measure audio start/played prefix. No latency or speech-quality number was measured here. Missing model/voice/key, secure context, native binding/resource or platform support must be unavailable with its concrete reason, not an empty successful transcript, silent fallback or fake device pass.
