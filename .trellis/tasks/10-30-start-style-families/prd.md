# Five distinct styles and control families

The user rejected one original kit arranged five ways. Deliver five genuinely different visual and widget families. The existing Workbench is a labelled retained candidate; Precision, Hearth, Folio and Prism are four new independent candidates. Keep the normal product default until a direction is chosen.

## Distinct candidates

| Family | Visual language | Actual control differences |
| --- | --- | --- |
| Precision | Compact, neutral, flat, technical | Native provider combobox and split list/detail, outlined fields/actions, row status |
| Hearth | Warm, soft, friendly, rounded | Large radio cards, filled fields, rounded CTA and pill switches |
| Folio | Cream paper, ink, serif headings, quiet rules | Text provider index/search, underlined fields, checkmarks and text actions |
| Prism | Dark ambient glass, translucent layers | Provider command dialog, inset fields, icon toggles and floating actions |
| Workbench | Existing pressed boards, notches and nameplates | Existing square pins, tiles and attached field plates; retained accurately |

Every family owns a complete window frame, navigation and real component/state board. The neutral review selector is infrastructure, not a shared product sidebar. Distinctness must include typography, material, shape and several control structures/interactions, not merely palette or grid.

## Functional boundary

Reuse the existing StartModel, theme controller, preview gesture/expression behavior and raw owned character. The four new families do not render original-ui/kit, old StartSlots, OriginalPetPreview or OriginalThemeStudio as their actual controls. Do not create another backend, recorder, credential store, history or configuration owner. Trusted URL and isolated review profile remain unchanged.

All existing model, region, browser-auth, save/test/active receipts, pause, desktop visibility, guide, chat, gesture, capture availability and theme editing remain reachable. Family defaults are review seeds; switching families must not persist preferences or clear model/Key drafts. Explicit edits still use the one theme transaction and rollback on leave.

## Acceptance

- [x] Five observable full-window style families and five actual state boards with different control types.
- [x] Same real actions and truthful saved/tested/active, available/pending/error/disabled states.
- [x] Shared owners, retained drafts/history, theme editing/custom variants/undo and user data preserved.
- [x] Actual 1200×800 and 880×600, light/dark, keyboard/focus/motion captures plus functional verification and independent style-range review.
- [x] Workflow distinguishes style exploration from layout variants; local commit/archive, no push or paid/live-account calls.
