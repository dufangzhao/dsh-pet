# Website-sourced control foundation

The user explicitly rejects self-design as the foundation. Select one suitable coherent basis from https://uiverse.io/ and https://www.morphicons.com/, actually adopt its source components/resources, and make only consistent additions. Do not deliver another original kit merely described as inspired by these sites. The five earlier original families are historical alternatives, not this foundation.

Scope: normal Start page and shared settings frame; sourced component/state board with raw upstream vs integrated examples. Preserve existing model/Key drafts, configuration/credentials/history/Core/capture/theme owners and trusted URL. Keep existing user data and custom palette values. Frontend implementation stays DeepSeek max.

## Source gate

- Choose concrete existing components with exact author/permalink, original HTML/CSS or package exports, version/revision and license text. Prefer an actual set/collection or same-author coherent visual vocabulary; do not claim an official complete design system if only several components exist.
- Website components must visibly remain the foundation: preserve characteristic geometry/material/animation and substantial source styles. Adapt labels, semantic HTML/ARIA, namespaces/tokens and responsive sizing. Record each adaptation. Missing controls can extend that foundation, not introduce a second original style.
- Morphicons is an icon-morphing library; verify its actual exported resources and glyph source, not falsely claim it supplies a full UI kit. Use concrete site-supported icon/animation data with attribution; no icons invented as the primary website resource.
- Preserve the complete original source/notice and provide live raw/integrated comparison. Do not treat a generic UI/UX generated plan or downloaded screenshot as source adoption.
