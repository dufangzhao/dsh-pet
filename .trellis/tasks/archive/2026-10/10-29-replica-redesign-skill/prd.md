# Reusable replica then redesign skill

## Goal

Create a lean project skill for replicating a known surface faithfully, proving its functions, then redesigning according to the functional contract and review options.

## Requirements

- Apply to later settings columns, pet bubbles and similar existing-product surfaces; do not hardcode this repository, model route or five variants as a universal rule.
- Reuse verified replica/evidence when it exists and separate functional parity from visual redesign.
- Cover exact source/version, real-versus-mocked validation, architecture constraints, asset license/provenance, model/expert selection, differentiated options, implementation and review.
- Use progressive disclosure and only genuinely useful supporting files. No extra workflow engine or placeholder documents.
- Preserve user authorization and intended scope; no invented permission/design gates or silent production replacement.

## Acceptance

- [x] Project skill has valid name/description/frontmatter, concise instructions and discoverable supporting material.
- [x] Skill creator validation passes and no scaffold placeholders remain.
- [x] Independent forward use on another surface produces scoped, evidence-backed outputs without copied product code, duplicate owners or unsupported completion claims.
- [x] The Start redesign case supplies a concrete usage example through links, not a second duplicated guide.
