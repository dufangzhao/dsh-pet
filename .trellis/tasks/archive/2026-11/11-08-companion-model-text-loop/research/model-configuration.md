# Replaceable model connections, default Magpie

Research only, updated 2026-11-08 after the owner's explicit decision: **ship Magpie as the default built-in model-connection plugin; allow another ordinary connection plugin to replace it. Connection configuration belongs to that plugin, not to Cortico.** Keep the existing runtime, permission kernel, credential broker, native response facade, Core and Docker executor. Do not add another TaskManager, model gateway implementation, secret cipher or product-state database.

This supersedes this note's earlier proposal to store model settings in Cortico Config. Scope follows the [current PRD](../prd.md), [repository instructions](../../../../../../AGENTS.md), [service contract](../../../../../spec/backend/companion-service.md), [actual stack](../../../../../spec/shared/project-baseline.md) and [parent Magpie research](../../../../11-06-unified-companion-architecture/research/magpie-routing.md). The completed [foundation evidence](../../../../../../qa/companion-acceptance.md#L7) proves local HTTP/Core/SQLite/Docker and controlled model transport, not a live account/model connection. This research inspected source/docs only: no secrets, inference, installation, service startup, tests, product edits, commits or new agents.

## Minimum generic connection port and plugin ownership

The following names are **proposed contracts**, not APIs already in the SDK. Keep one new capability-specific connection seam. A versioned marker/control capability such as `companion.model.connection@1` can expose JSON-safe `describe` metadata and support normal PluginManager selection. The native data path is the existing response facade through a host-private, activation-owned binding:

```ts
// Host-only facet; Request/Generation/options remain native and opaque.
interface TextModelBinding {
  readonly model: string;
  readonly client: ResponseClient; // existing respond(request, nativeOptions)
}
interface ModelConnectionPorts {
  // Owner is bound by the host activation; a plugin cannot choose another owner.
  bind(binding: TextModelBinding): () => void;
  // Only for adapters needing the existing native Responses implementation:
  authorizedResponses(baseUrl: string): ResponseClient;
}
```

`bind` registers one immutable binding for the exact `{pluginId,instanceId,generation,providerId}` and applied Config revision. Its disposer removes only that binding. `authorizedResponses` is injected by service composition: it builds the existing authorized client using that connector's private credential slot, never returns a key, and owns `close/drain` in the plugin's existing effect lifetime. A default factory and a custom factory both return ordinary `definePlugin(...)`, register the declared control provider and use the same private ports. One small activation-owned binding map is sufficient; PluginManager still owns install/enable/disable/trust/dependencies and TaskSupervisor still owns all work.

Do not implement a Magpie-specific `if` in Cortico or a registry of detached clients that bypasses plugin activation. A custom connection plugin must be registered through the existing [ServicePluginRegistration](../../../../../../packages/companion-runtime/src/plugin-host.ts#L36), receive the same documented private ports, and satisfy the same protocol/lifecycle contract. This proves programmatic replacement in this stage; a marketplace, arbitrary package upload or new install UI is separate scope. A marker capability alone does not authorize the private call: the host must check the selected provider and current generation before dispatch and before releasing its result.

Authority is deliberately two-sided:

- The consuming Harness holds its source task/`capability-use` lease for the selected model-connection capability, using existing `withSourceAuthority`; its owner/caller abort is propagated to the client. An explicit owner connection check consumes the port under the protected companion-host's declared capability lease instead, so checking a connector does not depend on Cortico already being ready.
- The host-private dispatcher also holds the connector's own source/config-read lease (the existing `files/plugin-data/read` permission convention) for the whole native operation. This applies to the credential-free fixture too: an active TaskSupervisor owner alone does not check source deny/fingerprint/revoke. The default Magpie native call additionally takes its connector-owned credential lease through `createAuthorizedModelClient(host, connectorPluginId, ...)`. Declare that connector's local `model-api-key`, supply its `hostCredentials`, and remove Cortico's obsolete credential requirement. Propagate all source/lease signals and await actual nested work; neither side borrows unrestricted core authority.
- JSON `describe` declares provider method permissions too. The native private port explicitly acquires its source/config-read/credential leases; do not claim `describe.methodPermissions` protects a call that does not traverse that JSON method. The current headless transport is host-owned and supports no generic network adapter; adding one later requires explicit readiness/permission work, not a decorative undeclared network permission or bypass.

For the built-in Magpie plugin, `authorizedResponses` suffices. A replacement fixture can `bind` its own compatible client without credentials. A future different wire protocol supplies its own authorized native adapter behind the same facade; it must not flatten private generation state or take ownership of canonical work. Native errors stay in the host closure, not a JSON capability result, as the existing transport already does ([model-client.ts:79](../../../../../../apps/companion-service/src/model-client.ts#L79)).

## Configuration, credentials and truthful status

Suggested default Magpie plugin Config (all nonsecret):

```ts
{ baseUrl: 'http://127.0.0.1:3425/v1', model: '', authMode: 'local-client-id' | 'gateway-key' }
```

The URL is a suggested default, not discovery/readiness evidence. The model is explicitly selected by the owner; no `provider/model` or group is silently invented. Empty model means unconfigured. `local-client-id` is restricted to an explicitly accepted loopback target. The pinned integration guide documents that local Magpie accepts an app-identifying bearer such as `magpie-dsh-pet`; this public label is **not an upstream provider secret**. Remote/shared Magpie requires an owner-provided gateway key, with HTTPS for nonloopback transport under the current native validator. Magpie owns upstream provider credentials/accounts; the companion needs its gateway access, not copies of vendor or DSH secrets. Keep that distinction in the form/status.

The protected companion-host Config stores a selector such as `modelConnection: 'pet.model-connection-magpie/magpie'`; default it to Magpie, with no hard dependency that prevents explicit selection of another connector. Keep the existing explicit `scripted/model` service mode separately; scripts are an intentional synthetic mode, never failure fallback. Preserve existing records and identity: add optional host selector/mode fields compatibly or use the existing migration contract, not profile reset. Connector Config is a new independent record; Cortico's existing `{}` record stays unchanged.

Persist through ConfigService only and declare reload application. Storage identity excludes generation ([store.ts:27](../../../../../../packages/host-kernel/src/config/store.ts#L27)). The [schema subset](../../../../../../packages/host-kernel/src/config/schema.ts#L89) supports closed objects/bounded strings/enums, not arbitrary `oneOf/pattern/uri`; validate target/auth cross-field semantics at the service boundary. Preserve explicit environment/options as connector overrides/seeds through CAS. Do not let [main.ts:13](../../../../../../apps/companion-service/src/main.ts#L13)'s current unconditional scripted default overwrite saved intent each restart.

Use the existing [suppliedSecret](../../../../../../packages/host-kernel/src/credentials/credential-broker.ts#L434) path for the gateway credential: owner-selected independent environment/secret-manager injection or a dedicated authenticated **memory-only** key submission, lost on restart. The accepted [safeStorage cipher](../../../../../../packages/host-kernel/src/credentials/secret-cipher.ts#L26) rejects Linux; no plaintext/identity cipher, credential-file fallback or DSH secret import. Require TLS or owner-controlled local/SSH access for remote browser key submission ([deployment guidance](../../../../../../docs/35-text-agent-foundation.md#L70)). Local client-label mode reports `credential.required=false` rather than pretending a secret was saved.

Bind a gateway credential to its connector identity and normalized target. A different connector or endpoint never inherits the prior connector's secret without explicit owner authorization. Replacing/removing a key creates a fresh opaque credential version even when nonsecret Config revision stays unchanged. No secret hash/suffix/readback. [hasSecret](../../../../../../packages/host-kernel/src/credentials/credential-broker.ts#L266) is only stored-presence metadata; it is not meaningful availability proof for this no-write supplied-secret path.

The public view should include selected/applied connector IDs, connector Config revision, applied revision, safe config fields, credential required/available/source, opaque credential version and a timestamped check `{state,commandId,configRevision,credentialVersion,error,elapsedMs}`. States remain `unconfigured/configured/validating/verified/failed`, separate from `agent.ready/busy/unavailable` and browser connectivity. Verified requires real completed inference for this exact connector/config/key binding. Invalidate for connector/model/endpoint/key changes, source trust/revoke, missing credential or restart; old check completions are fenced by connector and consumer owner generations. Keep current check state in memory; do not persist a generic “Magpie connected” boolean or infer a successful explicit check from a later normal reply.

Return saved/applied revisions and actual outcome. |

| `POST /api/model/test` | `{commandId, connector, expectedConfigRevision, expectedCredentialVersion}` admits one check of the exact active binding, returns 202 and publishes progress/final state through existing refresh/snapshot. No missing/unapplied/stale/inactive target I/O. |

Profile selection and plugin configuration are two independent CAS records, not an atomic cross-record transaction. Serialize their known write/apply order with the existing runtime control boundary; report a partial saved-but-unapplied result honestly and re-read revisions before activation. Do not invent a transaction/rollback layer or treat a saved receipt as applied behavior.

Reuse [getCommand/recordCommand](../../../../../../plugins/state-sqlite/src/state.ts#L581) for nonsecret intents and current-state convergence. Record test admission before I/O; duplicate command does not resubmit a paid request. After a crash, an old duplicate without retained outcome stays uncertain/unverified and needs a new explicit test intent. Never store keys in that payload/hash path, chat, URLs, events, logs, projections or artifacts. No network runs in a SQLite transaction. The [browser's 20-second JSON deadline](../../../../../../plugins/text-client/src/client/protocol.ts#L62) favors 202 plus one tracked existing source task over waiting for logical cancellation; actual drain may take longer.

The check uses the selected connector's same `ResponseClient` as replies. For Magpie that is the existing authorized native transport, fresh request “Reply with OK.”, no product history/files/tools, output cap around 256 tokens, fixed deadline around 15 seconds and internal `onEvent` so Responses SSE is exercised. Require `response.status==='completed'` and nonempty assistant output; never execute a returned tool call. `/api/hello`, `/models`, TCP success, an empty body or incomplete response does not verify generation. The check establishes text/stream connectivity; practical model-tool/file acceptance remains separate.

Pass native `diagnostic:true/role:'probe'` without rebuilding a native-options whitelist. Pinned Cortico uses `delays=[]` for diagnostics ([transport:105](../../../../../../node_modules/.pnpm/cortico@0.2.7/node_modules/cortico/src/providers/transport/response-http.ts#L105)); [native body:37](../../../../../../node_modules/.pnpm/cortico@0.2.7/node_modules/cortico/src/providers/openai-responses-compat/native.ts#L37) sets `store=false`. **One client HTTP request is not a promise of one vendor call:** Magpie may still classify/retry/fail over internally. Before live checks the owner must choose the gateway/model and approve the bounded upstream policy; prefer a concrete route with known routing behavior. Do not add model discovery, semantic routing or custom retries to the check.

Expose fixed `KernelError` codes only: auth failure, rate limit, explicit timeout, invalid target/protocol/unavailable response, network and existing source/credential refusal. Native response/error/attempt/partial objects remain opaque internally, including caller-specific options, as established by [current model tests](../../../../../../apps/companion-service/src/model-client.test.ts#L137). Wait for actual transport/credential settlement before clearing validating/admitting a replacement. This confirms local I/O cleanup, not remote vendor compute/billing cancellation; the [parent's cancellation evidence](../../../../11-06-unified-companion-architecture/research/magpie-routing.md#L127) records that distinction.

## Replacement lifecycle and useful work

1. Reuse existing `controlBusy/quiescing/pendingInputs` control state for connector apply/select, credential changes, Harness controls and check admission. Reject busy foreground changes with `conflict`; an independent Docker job alone does not block replacement. No second lock/queue/TaskManager.
2. Persist validated nonsecret desired intent via the existing ConfigService/profile CAS. Quiesce foreground admission and retire the old Harness projection, so no accepted round continues with a mixed client/model. [Harness retirement:343](../../../../../../plugins/harness-cortico/src/harness.mjs#L343) fences callbacks and checks actual drain.
3. Disable/drain the old connector under PluginManager; its effect unregisters the native binding and closes/drains the existing model broker. If actual cleanup is unconfirmed or [manager cleanup](../../../../../../packages/host-kernel/src/runtime/plugin-manager.ts#L537) leaves `pending_restart`, activate no replacement. Old client references cannot reborrow a new owner and contact a retired target. Endpoint-only changes also require actual connector reload, not `enable(active)`.
4. Enable the selected connector from saved Config, bind its current native facet, then rebuild/enable Cortico with the same persona/name plus the connector model/client. Check actual plugin states before reporting applied IDs/revisions. Failure retains desired intent but reports unavailable/unapplied, never scripted fallback, atomic rollback or silently revived Magpie. Missing gateway/credential does not prevent HTTP settings access.
5. Preserve state/execution roots, Agent identity, facts/messages, all task/execution/artifact/receipt IDs and independent work. New Core reads the bounded canonical context; old callbacks are fenced by both connector lifetime and [Harness source ports](../../../../../../packages/companion-runtime/src/runtime.ts#L554).
6. Fix/cover the existing [completion-delivery race](../../../../../../packages/companion-runtime/src/runtime.ts#L480): outcome/notice commits precede optional Harness `accept`, whose guard currently ignores quiescing. Withhold that optional delivery during replacement and read latest canonical state; an old failed delivery must not corrupt new readiness or rewrite completed work. No effect replay queue is needed.

Existing [start_work tools](../../../../../../plugins/harness-cortico/src/boundary.mjs#L22) already accept bounded Node ES-module code/input files/declared artifacts. No host-filesystem automation or new execution backend is needed. Model usefulness must be demonstrated through real model `start_work` admission and verified bytes, not direct `/api/tasks` calls credited to the model.
