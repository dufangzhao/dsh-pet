4. **Late callbacks — request-only cancellation trace addressed in frozen source, with a deterministic test.** [The dispatcher callback](../../../../../../packages/companion-runtime/src/model-connections.ts#L274) now fences the binding only when connector source/selection/policy is no longer current; an aborted per-request source signal suppresses the event without retiring a valid shared binding. 5. **Local Config revision and transport token — covered by the frozen source path; direct transport-specific regression not found.** [The host's ConfigService wrapper](../../../../../../packages/companion-runtime/src/plugin-host.ts#L152) notifies observers after a successful local save; the same `configs` instance is wired to the SDK host port. [ModelConnections](../../../../../../packages/companion-runtime/src/model-connections.ts#L55) aborts the activation token on a changed revision and fences any bound record. The [authorized transport wrapper](../../../../../../packages/companion-runtime/src/model-connections.ts#L160) combines that activation token with the context/caller signals and checks activation validity before and after native work. Thus host/SDK Config saves in this host reach the transport token in the inspected source. The [fixture tests](../../../../../../packages/companion-runtime/src/model-connections.test.ts#L240) exercise host and SDK saves against pending **bound fixture** work, including immediate abort and actual drain; no test was found that directly retains and exercises `ports.authorizedResponses()` across a Config save. This direct transport-specific assertion remains an evidence gap, not a claim that the implementation fails. This is host-local save observation, not a filesystem watcher. Explicit revoke aborts immediately; source file changes are observed at existing trust/validity or callback boundaries.

6. **Ingress — remote Host/Origin acceptance removed; deployment boundary accepted by parent.** [The predicate](../../../../../../apps/companion-service/src/server.ts#L65) no longer treats configured HTTPS `publicOrigin` as proof and rejects a nonloopback Host or Origin. [Tests](../../../../../../apps/companion-service/src/model-controller.test.ts#L194) cover direct remote and remote-host proxy headers; [HTTP cases](../../../../../../apps/companion-service/src/model-controller.test.ts#L377) check writable=false and 403 for those entries. The service can establish only the local TCP peer and loopback authority; it cannot distinguish an owner-controlled local client from a local forwarder rewriting the Host, or establish end-to-end TLS. The parent accepts this explicit deployment boundary: **a public proxy must not forward the private key route**; remote operators use host-side injection. The parent will make the supplied Caddy template explicitly return 403 for that route and document this once in the guide. These deployment changes are pending parent implementation and verification; no additional authentication framework or attempt to identify indistinguishable local proxies is requested.

7. **Rejected pre-mutation request poisoning — addressed in source and targeted test present.** The [save](../../../../../../apps/companion-service/src/model-controller.ts#L382) and [credential](../../../../../../apps/companion-service/src/model-controller.ts#L467) paths only persist a lifecycle error after `applicationChanged` becomes true. The [regression](../../../../../../apps/companion-service/src/model-controller.test.ts#L501) sends stale save and credential CAS requests against a healthy enabled binding and checks that its error, application and connector view stay unchanged. Await final run evidence.

## Historical findings reported to parent

1. **P1 — Same-ID probe admission can resend an inference request.** In the reviewed [model controller](../../../../../../apps/companion-service/src/model-controller.ts#L499), `getCommand` ran outside `withModelControl`. Two same-ID requests could both observe no receipt; delay B after its lookup while A records the intent and its check settles. B can then enter control, receive `duplicate` from the atomic `recordCommand`, and still start native work because the receipt status was not checked before starting the work at [the probe call](../../../../../../apps/companion-service/src/model-controller.ts#L518). The SQLite [record implementation](../../../../../../plugins/state-sqlite/src/state.ts#L589) confirms that a duplicate receipt is possible. Required evidence: a deterministic barrier around the second lookup and one observed network call. Existing focused coverage checks a sequential duplicate, not this interleaving.

2. **P1 — Credential retained across connector replacement.** The reviewed [slot implementation](../../../../../../apps/companion-service/src/model-controller.ts#L115) kept a slot per connector and only replaced a slot when that connector's target changed; [retirement](../../../../../../apps/companion-service/src/model-controller.ts#L229) did not clear the departing connector's slot. Trace: save Magpie in gateway-key mode and supply a key; switch to the synthetic fixture; select Magpie again without fresh input. The original Magpie slot is still available and [transport construction](../../../../../../apps/companion-service/src/model-controller.ts#L96) can use it. The [contract](../implementation-contract.md#L106) requires connector changes to require fresh explicit supply or injection. Required regression: switch away and back, verify no key availability or network use until fresh supply.

3. **P1/P2 — Replacement connector descriptions were not projected through the fixed settings allowlist.** The reviewed [description validation](../../../../../../apps/companion-service/src/model-controller.ts#L129) checked a JSON preflight and several top-level fields but did not validate or project `description.settings`; the [view](../../../../../../apps/companion-service/src/model-controller.ts#L270) returned that object directly. A custom connector projector could return extra private fields or a very large settings object within its individual JSON boundary. The former reaches model views; enough large descriptions can exhaust the aggregate snapshot budget before facts are projected. The [contract](../implementation-contract.md#L56) requires an allowlisted, bounded description. The existing [snapshot budget test](../../../../../../apps/companion-service/src/model-controller.test.ts#L442) uses preconstructed bounded metadata, so it does not validate the custom projector boundary. Required regression: malformed, extra-field and oversized custom descriptions, including preservation of facts.

4. **P2 — Native event callback was not fenced after abort or retirement.** The reviewed [dispatcher](../../../../../../packages/companion-runtime/src/model-connections.ts#L169) forwarded `onEvent` unchanged; the [Magpie transport wrapper](../../../../../../apps/companion-service/src/model-client.ts#L85) checked redaction without checking the combined authority signal. A controlled noncooperative native client can retain the callback, receive a revoke or retirement abort, and invoke the callback afterward; the final result guard does not suppress that event. The [design](../design.md#L51) requires late callbacks not to publish to a new generation. Required regression: capture the callback, revoke or retire, emit late, and verify suppression while physical drain is still observed.

5. **P2 — Revision checks did not abort already-running I/O.** The reviewed [binding guard](../../../../../../packages/companion-runtime/src/model-connections.ts#L153) compared Config revision before and after the native call; the in-flight signal did not include a Config revision-change signal. A connector's ordinary Config save during a pending call leaves old I/O running until settlement or its deadline, after which the guard rejects its result. Required regression: a pending no-secret fixture call followed by an owner Config revision change, with explicit assertions for cancellation and settlement.

   **Fingerprint observation boundary:** [permission leases](../../../../../../packages/host-kernel/src/permissions/kernel.ts#L327) recompute source trust when validity is checked. Explicit revoke invalidates active leases immediately; a disk modification is observable at existing trust/validity boundaries, where stale work or results are rejected. The review does **not** require instantaneous detection of arbitrary filesystem changes, and no filesystem watcher or kernel expansion is authorized. Existing tests distinguish changed source before admission from explicit revoke during a real socket call.

6. **P1/P2 — Configured HTTPS origin alone did not establish secure proxy ingress.** The reviewed [ingress predicate](../../../../../../apps/companion-service/src/server.ts#L64) accepted a loopback peer plus configured HTTPS `publicOrigin` and matching Host, with Origin optional. If a local reverse proxy forwards both plaintext HTTP and HTTPS virtual hosts to this backend preserving Host, an authenticated request through its HTTP vhost with the configured Host and no Origin (or a spoofed HTTPS Origin) is accepted for key entry and reports writable. The same predicate gates both projection and write, but it does not prove a TLS-only external path. The [contract](../implementation-contract.md#L164) requires a checked local reverse-proxy ingress and does not treat arbitrary headers as TLS evidence. Required evidence: exercise the actual supported proxy boundary, including a forwarded plaintext request.

7. **P2 — Rejected requests could poison the current lifecycle error.** The reviewed [save error handler](../../../../../../apps/companion-service/src/model-controller.ts#L429) and [credential error handler](../../../../../../apps/companion-service/src/model-controller.ts#L470) assigned every caught error to the persistent `view.error`. Trace: keep a healthy applied/enabled binding, submit a credential operation with a stale version, receive the correct 409, then read the model view. It can continue showing `error=conflict` despite the unchanged healthy application. The [DTO contract](../implementation-contract.md#L158) describes this field as the current application/lifecycle problem. Required regression: rejected stale or invalid request leaves the healthy lifecycle projection truthful.
