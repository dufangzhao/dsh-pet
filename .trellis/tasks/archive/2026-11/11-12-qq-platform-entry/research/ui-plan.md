# QQ 管理界面规划：Web 主管理

只读规划，2026-11-12。**未改产品源码**，未跑服务、未调模型、未连 QQ、未取用原素材。决策依据：[PRD](../prd.md) Q1–Q16（尤其 Q14 Web 主管理、Q15 记忆只 admin、Q16 文字必有）；边界与缺口见[运行时入口](runtime-entry.md)、[QQ UX 研究](qq-ux.md)、[AstrBot 研究](astrbot-qq.md)。

## 结论

**管理面全部落在服务 Web，桌面只显示状态 + 打开 Web 的入口。** 这是 Q14 已定的，不是候选。

界面上**不需要新样式体系**：Web 现有 `Dialog` / `Section` / `List` / `Field` / `Button` / `StatusBadge`（`packages/ui-kit`）加上 `tc-*` 布局类已能表达本文全部内容。唯一要新做的是**名单编辑器**（可增删行 + 校验），它是列表组合，不是新体系。

## 二、信息架构

Web 顶栏加一个 `QQ` 入口（与"模型""语音"并列），打开一个 **QQ 管理弹窗**。弹窗内按 `Section` 分区：

```
QQ
├─ 平台状态        [已连接·官方 WebSocket] / [未配置] / [已停用]
│
├─ 协议模块        ┌ 官方 QQ WebSocket ─ [已启用] [配置] ┐
│                  └ OneBot v11        ─ [未启用] [配置] ┘
│                  （两个独立模块，各自启停与连接状态）
│
├─ 全局设置        · 主人/管理员成员名单
│                  · 公开 facts 的发布权（只 admin）
│                  · 语音回复总开关（文字恒有）
│
├─ 群设置（按群）  · 该群的近期上下文条数
│                  · 唤醒词 / @ 触发
│                  · 主动回复：开/关 → 机制（规则概率 | Magpie judge）→ 参数与预算
│
├─ 准入名单        · 私聊白名单（人）
│                  · 群白名单（群）
│
└─ 媒体            · text（必有，不可关）
                   · image / voice / file（按协议显示真实支持）
```

### 关键结构决定

**两个协议模块是并列的两张卡，不是"选择其一"的单选。** Q1 已定首版都支持。各自有独立的启用开关、连接状态、凭证。若只启用一张，另一张显示"未启用"而不是消失——用户随时能看到"我现在走哪条路"。

**全局与按群是两层，不是一张平表。** 全局设置对所有群生效；群设置覆盖单个群。界面必须先选群再改群设置（`List` 选群 → `Section` 编辑），不能让用户在一张表单里同时看到"全局唤醒词"和"某群的唤醒词"。

**准入名单与成员角色是两件事，分两处。** 名单回答"谁能进来"，角色回答"进来后能做什么"。混在一起会让"加进白名单"被误读为"给了管理员权限"。

## 三、每条决策对应的界面

| 决策 | 界面落点 | 必须说清的事 |
| --- | --- | --- |
| Q7 白名单多人私聊 + 指定群 | 准入名单两个列表 | **空 = 无人准入**（不是不限）；列表为空时用 `EmptyState` 明写 |
| Q8 普通成员受限、主人分级 | 全局设置里的主人/管理员名单 | 群管理员 ≠ Agent 主人；界面不读 QQ 群主身份 |
| Q9 私聊按人/群按群、公开 facts 共享 | 全局设置的"公开 facts 发布权" | 只有 admin 能标记公开（Q15） |
| Q10 近期 context + @/唤醒词 + 主动 | 群设置 | 三类触发分别开关；"近期上下文条数"是每群独立 |
| Q11 规则概率 + Magpie judge 都可选 | 群设置的主动回复机制 | judge 需要**模型选择 + 调用预算**，是独立配置域 |
| Q12 四媒体 | 媒体区 | 按当前协议显示真实支持；未验证的标"待验证" |
| Q15 长期记忆只 admin | 全局设置 + 成员区说明 | 普通成员"能用可见记忆，但不能改"，界面上要有一句话 |
| Q16 文字必有、语音附加 | 媒体区 + 语音回复开关 | 开关只控制**附加语音**；文字不可关闭 |

### Q16 的界面细节（容易做错）

语音开关的文案必须是"**额外发送语音**"，而不是"语音回复"。因为 Q16 明确文字恒有、不能用音频替代文字。开关关闭时不该暗示"这条回复没有内容"，只表示"不额外发语音"。

若某协议不支持语音（官方 QQ 与 OneBot 能力不同），该开关显示"当前协议不支持"而不是可点但无效。

## 四、状态：saved / applied / accepted / unknown

Q4 要求分层。界面上每一层都要有落点，且不能合并：

| 层 | 界面位置 | 措辞 |
| --- | --- | --- |
| 配置已保存 | 表单底部 | "已保存" |
| 连接已应用 | 模块卡状态徽标 | "已连接 · 官方 WebSocket"（含账号标识） |
| 平台已接受 | 消息/发送记录（若展示） | "平台已接受" / "平台拒绝" / "结果未知" |
| 实际送达 | **不展示** | 无此事实 |

**"结果未知"必须是一个可见状态**，不是一个被吞掉的错误。OneBot 的 `status=async` 就是明确的"无法获知成败"（[astrbot-qq.md:124](astrbot-qq.md#L124)），界面要如实说，不能显示成功也不能自动重发。

## 五、桌面：状态 + 入口，不传 token

桌面只做两件事：

1. **显示 QQ 连接状态**（已连接/未配置/已停用 + 协议名）。数据来自服务端视图，桌面不自己判断。
2. **一个"打开 Web 管理"的入口**，打开服务 Web 的 QQ 页。

**关键约束：URL 里不能带 owner token。** 现有连接令牌的生命周期是"这次连接"，明确不写进 URL、不写进 web storage（见[共享桌面入口研究](../../../../11-06-unified-companion-architecture/research/shared-desktop-entry.md)）。所以入口只能是"打开 Web 首页/QQ 页"，让用户在那里自己完成认证，**不能**拼一个带凭据的深链。

如果桌面本来就没连上服务，这个入口应说明"先连接服务"而不是打开一个会 401 的页面。

## 六、名单编辑器（唯一新做的控件）

需求：增/删一行、每行一个标识、可校验格式、可标记角色。

复用：`List` + `ListItem` 显示已有条目（`trailing` 放删除按钮），下方一个 `Field` + `Button` 添加。**不引入新组件库、不引入表格组件。**

校验要点：
- 私聊与群的标识格式不同，各自校验；
- 重复项要拒绝并指出；
- 空列表不是错误，但要显示"当前没有任何人/群被允许"。

## 七、明确不做

- 不加多账号槽位：首版每协议一个实例，沿当前 host 的 `default` 实例约束。
- 不做 QR 登录：Q13 的 SnowLuma 是兼容线索，不是本产品的登录 UX；且其版本与端点未验证。
- 不新增网页样式体系：只用 `ui-kit` + 现有 `tc-*`。
- 不让普通 QQ 成员访问任何管理 API（Q14 明确）。
- 不做"已读/已送达"（无此事实）。

## 八、待技术确认（归 GPT）

- **服务端 QQ 配置路由**：今天只有 `GET /api/plugins` 与 `POST /api/plugins/{id}`，没有配置读取/保存。Web 主管理需要新增（[server.ts:355](../../../../../../apps/companion-service/src/server.ts#L355)/[:453](../../../../../../apps/companion-service/src/server.ts#L453)）。
- **视图字段**：`CompanionPluginView` 只有 id/name/state，不够表达"已连接·官方 WS·某账号"。
- **配置 Schema 表达力**：名单数组、每群覆盖、概率、模型引用能否用现有 Config Schema 表达，还是需要结构化扩展。
- **归属缺口**（来自 [qq-ux.md](qq-ux.md#L138)）：消息无平台/发送者/会话字段；多输入折叠为 `inputIds[0]`；`startTask` 丢弃 origin——这三条不解决，界面上"谁在哪个群说了什么""看/停自己的 work"都没有数据来源。

## 九、冻结

以上为 Web 主管理的界面规划与复用清单，不构成实施批准。服务端配置路由与视图字段就绪前，界面无法落地。
