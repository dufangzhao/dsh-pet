# M0-05 · 用户手动 F8 与原生轮询对照

状态：**本机有限样本通过边沿捕获；临界时长分类存在观测分歧**。用户明确选择现在配合手动F8；本实验没有键盘注入，只在自有原型窗口获得焦点时读取F8，不记录其它键或音频。

## 实测

[原始数据与逐项分析](V-key-live-results.json)包含窗口before-input-event与Electron Node工作进程Koffi/GetAsyncKeyState的独立事件记录。实际运行Electron45.0.0/Node24.22.0，10ms请求周期；首次F8开始60秒采样，随后自动关闭，启动器读回exitCode=0。

| 项目 | 结果 |
| --- | --- |
| 窗口事件 | 11次按压，22条down/up；自动重复排除 |
| 原生轮询 | 22条down/up，数量与类型顺序全部匹配 |
| 窗口计时轻点 | 147–244ms |
| 窗口计时明显长按 | 1679ms、2194ms |
| 实际轮询间隔p50 / p95 / max | 15.4979 / 16.1742 / 27.8360ms |
| 250ms分类 | 第1次不一致；其余10次一致 |
| 焦点 | 焦点变化发生在首个样本之前；采样段没有观测到中断 |

第一下窗口事件时长244ms、原生采样264ms；按250ms分别得到tap/hold。两个时间源是**应用收到事件与轮询观测的时间**，都不是硬件时间戳，更不是用户意图的直接真值。负时间差表示原生状态先于应用事件到达被观察到，不是负的硬件延迟。

## 初值处理

主会话建议暂定300ms，为本次稍慢的轻点留余量；在同一组数据上，300ms的分类全部一致，但这只是候选复算，不是独立复验，也不能消灭任意阈值附近的量化误差。向用户请求确认未收到回复并超时，**当前代码/决策仍保留250ms**，不得把超时视作批准。

F8仅是本轮用户确认无冲突后配合的实验键，不是产品默认热键。M3-02仍需检查全局/组合键、焦点切换时的持键、锁屏/休眠、高负载、极短按压和取消链路。本次样本最短147ms，不能用它宣称20/50ms等更短真实按压无漏。

## 实现与复现边界

- [父进程观测](probes/key-live-main.cjs)：只接受自有窗口焦点内的F8事件，排除自动重复。
- [原生只读工作进程](probes/key-live-worker.cjs)：先核对前台HWND，只在匹配时读取F8高位。
- [清环境启动器](probes/key-live-launch.mjs)：固定Electron包和实验入口，不透传任意启动参数。
- 角色“倾听/待机”变化只是轮询边沿的模拟反馈，不录音、不调用ASR/LLM。
- 焦点切换中未配对的按键、测试窗口提前关闭或worker失败应记不完整，不能算通过。本报告只评价这次完整配对的数据。

需要真实人工输入才可复现，不应在无人配合时将零样本算成功。
