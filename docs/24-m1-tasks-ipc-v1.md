# M1-04 任务、流与进程通道基线

状态：本轮实现接口。沿用契约v1，控制与媒体分离；不得把内存/单进程测试外推为跨进程已通过。

## 任务

TaskSupervisor是宿主对象，不交给插件。run(owner, work, options)创建宿主生成的taskId，绑定owner世代及其撤销信号，返回TaskHandle。任务只有一个终态；取消、时限、停用均立即结束可见结果并拒收晚到结果，但不谎称未合作代码已停止。仍在执行的晚到work计入容量，不能通过反复取消无限绕过预算。

TaskHandle提供result、cancel、snapshot；工作上下文有taskId/owner/signal/本地deadline；资源清理由本层与租约的撤销信号监听完成，不额外暴露宿主对象。任务事件仅为started/completed/failed/cancelled固定元数据，不存用户内容；业务分块走流。开始/终态各最多一次，回调异常不扩散。输入/输出JSON按契约预算校验，异常固定分类。

能力调用在任务建立时绑定已显式选择的实现。invokeCapability先检查任务/调用者及提供方，再通过授权租约，最后调用受控实现；默认没有authorizer即拒绝。租约只取得一次，停止/撤权/截止和结果交付时复核。提供方实际系统操作仍须另过自身SDK权限门，不把capability-use当网络/凭据权限。

## 媒体流

BoundedMediaChannel绑定streamId/taskId/owner，严格检查连续序号与字节数；每块<=256KiB，队列最多8块且<=2MiB。push不接受超量数据，waitWritable等待容量但不持有待写数据（等待者也有界）。close要求终止序号匹配并排空已有有效数据；cancel/失败清空缓存、结束读写等待，不能把取消当正常完成。单消费者，迭代return取消流。

验证入口读取描述符并复制字节，禁止共享内存/Proxy/访问器绕过。流错误只给固定KernelError。控制通道不承载音频或明文凭据；凭据敏感通道后续单独接线。

## 进程通道

优先使用父进程持有的匿名IPC，不开放TCP/WebSocket端口。通道初始化绑定session与peer身份；每个消息再校验Schema、预算、owner/世代、方法白名单、request/task关联、去重、序号。不能以载荷自报owner代替通道身份。

RPC取消按宿主请求映射转发；断开/超时结束待决请求并清理监听，晚到响应不重新交付。媒体使用独立字节通道及明确长度帧，不混在JSON控制管道。先验证所选Windows/Electron传输机制，再接运行区与预加载桥。M0原型桥保持原样。

## 验收

单元测试覆盖晚到/重复完成、取消各阶段、owner世代失效、授权拒绝/撤销、任务及队列容量、序号/终止、等待取消/断开。真实Electron进程验证RPC、媒体与崩溃清理；前台UI不应依赖重计算。未接通的部分明确列出，不把fake transport测试算成进程证据。

## 本轮实现补充

TaskHandle的result代表逻辑结果，settled只在底层work结束后完成；工作仍挂起时继续计入容量。事件重入有序，超时同时检查单调截止点，不能仅依赖定时器及时被调度。

输入关闭不等于所有数据已消费；有排队数据时取消仍会清空，排空后的正常终态不被改写。流等待者看到既有终态原因，而不是被其局部信号重新解释。媒体额度初次明确授予，后续只返还已发送未确认帧，end等确认债务归零。

控制消息的id在每个方向连续使用m-N，接收方严格检查以避免无界历史集合；未指定taskId的RPC自动分配局部取消域。流控制API不能覆盖会话头或伪装为request。

Windows实测采用父子进程原生IPC作为控制通道，额外fd4匿名双向管道作为媒体通道；不开放TCP端口。真实探针通过仍不代表正式运行区与预加载桥已接通。
