# 首个实用闭环：语音听写 PRD v0.1

状态：主闭环优先级已确认；细节与最终MVP范围未冻结。依据[ADR-0007](adr/0007-dictation-first-workflow.md)。本文没有产品实现或测试通过的含义。

## 目标与成功定义

用户能够在明确支持的Windows应用输入位置，通过语音形成文字，并在可理解、可取消的流程中安全提交。角色和设置台是入口与反馈，不要求用户先打开完整聊天会话。

“每天愿意用”需要同时成立：识别可用、目标不出错、原文不被意外覆盖、交互不失去响应、错误能恢复。只演示一次成功输入不能作为完成标准。

## 最小链路与能力职责

1. **触发/音频采集**：创建本次任务，显示录音状态和输入模式；提供音频帧与设备状态。
2. **ASR提供者**：消费音频，返回临时/最终转录及错误；不读取其他应用，也不执行输入。
3. **听写编排**：处理结束、取消、预览/提交和文本版本；锁定本次目标/配置语义。
4. **输入目标与提交能力**：验证支持条件、焦点/目标、输入动作与权限，提交后返回结果/验证限制。
5. **界面**：桌宠状态、听写气泡或面板、设置台共用同一任务状态，不出现一处完成另一处仍录音。
6. **宿主**：路由、取消、授权、资源归属、诊断和配置；不绑定某个ASR实现。

## 状态与用户操作（草案）

| 阶段 | 必须让用户知道 | 可用操作/约束 |
| --- | --- | --- |
| 未就绪 | 缺模型/麦克风/授权/支持条件中的哪一项 | 配置或修复；不静默启动失败 |
| 就绪 | 当前是听写，不是发送给聊天模型 | 开始、切模式或配置 |
| 正在录音 | 正在收音，目标/模式是什么 | 结束录音与取消为不同语义 |
| 正在识别 | 临时文字与最终文字不同 | 取消；不重复提交临时版本 |
| 待提交/预览 | 将写入的内容及目标 | 是否启用该步骤待选；可修正/放弃 |
| 正在提交 | 系统输入可能即将或已经发生 | 不触发相同任务重复提交 |
| 已确认/未能确认 | 观察到的结果与证据限制 | 不把接口返回成功伪装成内容完全一致 |
| 失败/已取消 | 失败位置、是否已产生副作用 | 恢复文本或安全重试，不盲目再次注入 |

关闭显示面板、结束录音、取消任务和停止整个应用不应混为同一操作。具体快捷键和交互节奏待选。

## 数据与权限边界（要求方向/待细化）

- 麦克风、网络上传、剪贴板和输入注入分别说明；识别器不因拿到音频就获得系统操作权限。
- 本地/云策略明确后，再规定外发数据与提供方；不得在本地失败时未经允许切云上传。
- 密码框、焦点突变、权限提升窗口和不支持应用需要明确拒绝/回退，不尝试绕过系统边界。
- 录音、转录、诊断和历史的保存策略待选，不把“本地识别”自动等同于“从不保存”。
- 故障回退可保留可复制文本，但复制动作和剪贴板恢复策略也需要明确。

## 范围建议：不要让首闭环被全平台建设拖住

用户已选择首版完整本地/云双路径，因此至少各有一个实际可用ASR提供方，另配一种验证过的输入路径、一组真实应用场景、基本桌宠反馈和相应设置。mock只做契约/故障测试，不代替真实双路径；仍不需要首版集成所有云服务。详见[ASR双路径规格](10-asr-providers-and-dataflow.md)。

自然语音聊天、音色克隆、完整角色制作器、自主电脑操作、公开插件市场不建议作为首条听写链路完成的阻塞条件；这只是范围建议，最终版本安排需用户确认。

## 验收覆盖

复用[UC-02的AC-DI-01至05](07-use-cases-and-acceptance.md)，并增加以下待量化检查：

| 类别 | 必须覆盖 |
| --- | --- |
| 语音样本 | 目标语言、短句/长句、静音、混说、姓名/术语、背景噪声 |
| 输入目标 | 首批应用、普通/富文本、已有文字、光标/选择区、切窗与最小化 |
| 生命周期 | 初次模型准备、冷启动、重复录音、设备拔插、休眠恢复、停止/退出 |
| 故障 | 识别崩溃/超时、网络失败（如有）、注入结果未知、取消后晚到结果 |
| 交互 | 持续录音/模型准备时拖拽和停止仍响应；键盘入口和错误说明清楚 |
| 隐私 | 不向未批准目的地发音频；敏感字段不默认写日志；目标与权限可核对 |

精准率、识别/提交耗时、输入反馈、帧时间与资源阈值待选择后写入测试标准；当前不编造“流畅”数值或通过结果。
