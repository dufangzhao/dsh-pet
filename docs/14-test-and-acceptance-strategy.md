# 测试与验收策略草案 v0.1

状态：方法草案。目前还没有产品代码和测试；本文规定“测什么、怎么测、证据是什么样”。具体性能数值、目标应用清单和工具版本，等你确认后再填入。

## 1. 四条原则

1. **证据分级，不混用**：契约测试通过、真机端到端通过、用户日常可用，是三种不同结论。每条验收记录都写明证据类型。
2. **可复现才能宣称通过**：记录Windows版本、硬件、应用版本、模型或服务版本、配置、输入数据和步骤。
3. **失败路径和成功路径同样重要**：取消、晚到结果、断网、崩溃、焦点变化都必须有用例。
4. **先定测量方法，再定数值**：在目标机器上测量之前，不写“多少毫秒以内”的承诺。

## 2. 测试层次

| 层次 | 验证什么 | 工具候选（未选定） | 何时运行 |
| --- | --- | --- | --- |
| 单元 | 状态机、能力路由、配置迁移、错误分类等纯逻辑 | TypeScript单元测试框架 | 每次提交 |
| 契约 | 插件是否符合清单、生命周期和能力规则；用模拟提供方做故障注入 | 自建契约测试套件 | 每次提交；插件发布前 |
| 集成 | 宿主与真实插件跨进程协作：取消转发、世代号、资源释放 | Node测试 + 子进程 | 每次合并 |
| 界面 | 设置台、桌宠状态、贡献点的出现与清理、键盘可达 | Playwright对Electron的实验性支持（以锁定版本文档为准） | 每次合并 |
| 真机端到端 | 真实麦克风、ASR、Windows文字输入、目标应用 | 手工脚本 + 半自动记录 | 里程碑与发布前 |
| 性能 | 交互响应、帧时间、资源占用、听写分段耗时 | 自建埋点；Electron contentTracing；Windows性能工具（待选） | 里程碑与回归 |
| 隐私与权限 | 未授权调用被拒、数据只去批准的目的地、日志无敏感内容 | 契约测试、网络观察、日志扫描 | 里程碑与发布前 |

## 3. 听写耗时：分段测量，不只看总数

| 时间点 | 含义 |
| --- | --- |
| T0 | 用户触发开始 |
| T1 | 界面显示“正在录音” |
| T2 | 用户结束录音 |
| T3 | 最终转录可用 |
| T4 | 发出提交动作 |
| T5 | 在目标应用中观察到文字（仅限能回读时） |

- **输入反馈** = T1 − T0：按键后多久看到反应。
- **识别收尾** = T3 − T2：说完后多久拿到最终文字。
- **提交** = T5 − T4：文字多久出现在目标应用。
- **松键到上屏** = T5 − T2：用户感受最直接的等待。

冷启动（首次加载模型）与热状态、本地与云端、短句与长句要分开统计。使用中位数和较慢一端的分位数，不用单一平均值掩盖偶发卡顿。

## 4. 交互流畅度：在负载下测

| 指标 | 测量方式 |
| --- | --- |
| 输入反馈延迟 | 点击或热键到可见状态变化的时间 |
| 桌宠帧时间 | 动画和拖拽时的帧时间分布与掉帧次数 |
| 长任务 | 主进程与渲染进程中超过阈值的阻塞次数（浏览器Long Tasks API以50ms定义长任务；本项目阈值待定） |
| 资源占用 | 空闲与工作时的CPU、内存、显存；停用插件后是否回落 |

负载场景：空闲 / 录音并本地识别 / 下载模型 / 云端识别遇到慢网络 / 插件崩溃并重启。“丝滑”的验收标准是：在这些场景下，上述指标都满足你选定的数值。

## 5. Windows文字输入兼容矩阵（模板）

| 应用及版本 | 控件类型 | 光标处插入 | 替换选区 | 保护已有文字 | 能否回读 | 结论 | 证据 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| <待你提供> | 普通 / 富文本 / 网页 / 终端 / 输入法组字中 | | | | | 支持 / 有限 / 不支持 | |

首批应用由你提供：你每天在哪些软件里打字。另有三类**必须拒绝**的固定用例：密码框、更高权限（管理员）窗口、锁屏或安全桌面。结论只针对记录过的应用版本，不推广为“任意应用可用”。

## 6. 双路径ASR测试

沿用[ASR双路径规格](10-asr-providers-and-dataflow.md)中的矩阵，并准备一套录音样本：普通话、中英混说（若首版支持）、人名与术语、背景噪声、静音、长句。

样本由你自己录制，默认**不提交到Git**，因为录音属于个人数据；是否入库由你决定。云端路径必须用你的真实Key至少完成一次端到端验证；只用模拟提供方测试，不能宣称云端已验证。

## 7. 契约测试用的参考插件

测试宿主本身，需要一组“故意有问题”的参考插件：

| 参考插件 | 用途 |
| --- | --- |
| 脚本化ASR | 按剧本输出临时和最终转录，可设置延迟与错误 |
| 记录型文字输入 | 不真正输入，只记录提交内容与次数，用于检查重复提交 |
| 会崩溃的插件 | 在启用中或运行中退出，检查隔离与恢复 |
| 慢插件 | 不响应取消，检查停用时限与强制回收 |
| 泄漏插件 | 停用时故意不清理，检查宿主能否发现残留 |

## 8. 故障注入清单

- 提供方在启用中或识别中崩溃
- 提供方不响应取消
- 云端：断网、超时、限流、鉴权失败、额度不足
- 本地：模型文件缺失或损坏
- 麦克风拔出或被占用
- 录音期间切换焦点；目标窗口被关闭
- 系统休眠与唤醒、锁屏
- 两个插件请求同一个热键
- 任务进行中停用插件

## 9. 验收记录格式

每条记录包含：验收编号（如AC-DI-01）、日期、构建版本或提交号、环境、步骤、预期、实际、证据（日志、截图、录屏）、结论、未覆盖项。建议存放在仓库的qa目录；原始录音和录屏默认不入库。

## 10. 完成定义草案

一项功能同时满足以下条件，才算完成：

1. 对应的单元测试和契约测试通过。
2. 对应验收编号有真机记录，结论为通过。
3. 性能分段已测量，并满足你选定的数值。
4. 用户说明和插件说明已更新。
5. 第三方许可声明已更新。
6. 停用和卸载后没有未解释的残留。
7. 代码审查通过。
