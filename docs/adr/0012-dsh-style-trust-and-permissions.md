# 插件信任与权限采用DSH方案：可信插件、权限预设、一次性审批

用户要求Q11按DSH的方案执行。DSH中，插件管理器安装的宿主代码在进程内运行、位于工作区沙箱之外，动态插件的node:vm隔离也被明确说明不是安全边界；DSH不对插件代码做沙箱，而是控制敏感操作。权限预设把执行范围和审批策略打包成命名档位；超出档位的操作需要一次性审批，审批只对该次请求有效；审批通道缺失时操作失败；每次请求与结果都写入审计记录。本项目照此执行，对应原Q11的A路线。

## 在本项目中的具体做法

- 插件代码按可信的本机程序对待。安装或启用插件本身是一次信任决定，需要用户明确确认；插件依赖的构建或安装脚本另行确认，不随安装自动执行。
- 录音、云端上传、文字输入、剪贴板、屏幕捕获、电脑操作等敏感能力，由权限预设规定“自动执行”或“需审批”。默认预设的具体内容随相关功能确定。
- 审批只放行这一次，不形成长期授权；想长期免询问，就切换或调整预设。这样停用、关闭或重启后不会残留旧授权。
- 审批通道不可用时默认拒绝；等待审批时取消任务会撤回询问，晚到的答复被丢弃。
- 每次审批请求与结果写入审计记录。
- 重计算的进程分离继续保留，用于流畅与故障隔离，不作为安全边界。

## 后果

- 首版不承诺阻止恶意插件绕过SDK直接访问系统；安装来源与信任确认是主要防线。
- 契约草案中的“授权范围与期限”改为“预设决定范围，审批一次一放”。
- 以后若开放陌生第三方插件生态，可评估受限运行环境，并以新ADR补充或替代本决定。
