# 采用能力插件与受控界面贡献点

项目采用“能力 + 受控界面扩展”模式。插件除了提供可替换的模型、语音、工具等能力，也能按统一规范注册设置页、快捷命令/按钮和结果/任务面板等界面入口；宿主统一管理入口、主题、权限、状态与生命周期。首版具体开放的贡献点清单随MVP另行确认。

用户同时要求扩展性强和交互顺滑。只开放能力、固定全部普通界面会限制完整功能扩展；从首版开放可重组的整套工作台则增加不必要的兼容和性能治理成本，因此选择受控贡献点。

## 考虑过的其他选项

- A：能力可换、普通界面固定。实现更简单，但扩展常要改主程序或另开应用。
- C：高度可定制工作台。表达能力更强，但首版范围、兼容和维护成本更大。

## 后果

- 插件不能任意修改宿主DOM、绕过授权或劫持全局快捷键。
- 卸载/停用必须同步清理入口、监听、任务和资源，不能留下失效按钮。
- 统一契约需包含配置、版本、状态、错误与取消，不只是加载模块。
- 慢插件与重计算不能阻塞日常输入和角色交互；隔离技术和性能阈值仍待选。
- 该决定不选择Cordis/Cortico/DSH、Electron/Tauri或代码许可证。
