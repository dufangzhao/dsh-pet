# 使用统一单层插件模型，以能力依赖图协作

所有功能与能力实现采用同一种插件清单、注册/管理和生命周期规范。功能编排、能力提供、工具、UI是可组合的职责，不形成两套插件类型、SDK或加载器；同一插件可以同时提供和消费能力并贡献受控UI。

用户指出DSH中功能插件和提供者处于同一层，功能插件主要只是官方自带。此前草案的“两层”本来是职责区分，却容易导出不必要的架构等级，因此按用户意见澄清并经确认采用统一模型。

## 后果

- 官方预装、官方按需、外部安装是来源/分发信息，不是插件层级或自动授权依据。
- 小宿主的少量启动/管理/停止基础模块可受保护；可选内置功能也按同一契约管理。
- 通过能力依赖图保留共享、替换和独立升级，不退回把引擎写死在大功能包里。
- 同一能力多个实现按显式配置路由，不以加载先后隐式覆盖。
- 单层逻辑模型不等于同一进程；UI、重计算、原生与第三方插件的运行隔离另行设计。
- 可以有配置分组、作用域或安装套装；它们不产生另一套插件标准。
- 具体框架版本、清单字段、包格式和运行机制仍待选；不承诺直接兼容DSH的现成插件。
