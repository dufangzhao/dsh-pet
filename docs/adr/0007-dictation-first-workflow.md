# 优先交付语音听写到目标应用的日常闭环

产品的第一条完整实用验证路径选择“语音听写到目标应用”，而不是先做角色语音聊天或屏幕理解/电脑操作。该选择决定开发优先级，不自动删除其他功能，也不宣称最终MVP范围已经全部冻结。

听写直接产生并提交文本，不要求先经LLM规划。桌宠、设置台与插件机制先以支撑这个闭环的最小完整范围实现，再扩展其他能力。

## 取舍与后果

- 可以优先验证日常效率价值与能力解耦；相较角色聊天，需要特别重视目标/焦点、原文保护与应用兼容。
- 初期应建立明确的支持应用矩阵，不承诺任意应用、管理员窗口或密码框可输入。
- ASR本地/云、语言、触发/提交方式、注入策略和性能阈值仍待选择。
- 角色语音聊天、朗读、声音制作、屏幕/操作能力的具体版本安排后定，不因选择听写就自动标为已取消。
- 该决定没有授权立即实现或在用户电脑上执行输入测试。
