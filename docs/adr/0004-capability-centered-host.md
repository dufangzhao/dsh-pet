# 采用能力/插件中心的架构，Agent是可替换能力

项目以能力与插件契约为架构主干，而不是把所有行为都围绕一个固定AI角色内核组织。语音识别、听写提交、TTS、音色、人设/外观、视觉、电脑操作、模型/Agent分别有清晰职责；确定性工作流无需先交给LLM规划。

优先复用适合的现成插件基础框架，避免重新实现所有依赖与生命周期机制。Cordis是候选，但用户尚未选择具体发行线/版本；须通过依赖、资源清理和插件运行验证，再形成具体技术基线。

## 比较与代价

- 相比以Cortico的角色/会话组织为主，能力中心更符合独立实用功能和可替换扩展；并不意味着Cortico不能实现这些行为。
- 相比所有插件设施自行实现，复用基础框架可减少通用机制开发，但仍需维护自己的产品契约与兼容层。
- 需要自行定义路由、受控UI贡献点、媒体流、任务/取消和权限代理；框架不能自动解决这些问题。
- 单纯模块解耦不等于故障或安全隔离；具体进程和沙箱策略仍待选。
