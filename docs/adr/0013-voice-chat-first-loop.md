# 首条闭环改为跟桌宠语音对话；跨应用听写改为后续插件

Q6曾记录为“语音听写到目标应用”。用户随后澄清：首版的“语音输入”是对桌宠说话，识别结果只进入桌宠自己的对话，由AI回应；“替用户往其他软件打字”以后作为可卸载的内置插件再加。本决定取代[ADR-0007](0007-dictation-first-workflow.md)。

## 后果

- 首版闭环：说话键 → 录音 → 识别（本地或云端，用户自选）→ 桌宠对话 → AI流式回复。AI对话模型因此进入首版。
- 已定的识别方案不变：本地sherpa-onnx两个候选模型、云端三家自带Key、普通话加中英混说、说话键一个键两种用法。
- 跨应用写入相关的Q13、Q13b、Q15决定保留，留给将来的听写插件；首版不实现目标绑定、文字注入和回读。
- Q18在首版只剩说话键状态检测；跨应用文字输入的实现路线随听写插件再定。
- 安全策略中“写错目标、覆盖原文、密码框、剪贴板、终端误执行”等风险，在听写插件加入时才适用；录音外发、Key保护、插件信任等仍适用于首版。
- 听写插件与语音对话共用同一套识别能力，不另建识别链路。
