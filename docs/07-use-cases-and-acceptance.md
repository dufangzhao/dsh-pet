# 候选使用场景与验收草案 v0.1

状态：需求澄清材料，未确定MVP。场景来自[产品基线](00-product-brief.md)；下面的流程/验收是设计建议，不代表实现、测试已通过或用户已经选择所有默认行为。

## 共同规则

- 每次任务可辨认来源、输入目标、当前阶段和结果；不能将请求发送成功当成任务成功。
- 停止录音、取消识别/对话、停止播放、关闭面板是不同动作，不以同一个不明确按钮混用。
- 失败时明确是否已经发生副作用；重试不能悄悄重复文字输入、付款、发送或删除。
- 提供方、音色、角色与工作流可分别选择；一次任务中的提供方和配置应可追溯。
- 所有“后台、持续、自动、记住授权”的行为需要单独选择范围与期限，不从普通功能需求推定。

## UC-01 · 与桌宠语音对话

**来源：**U-01。**范围状态：**候选；触发方式、本地/云、自动提交和打断策略待选。

**前提：**有可用麦克风与当前授权；识别/模型可用；未授权时先解释需要什么，不自动扩大权限。

**主要流程：**

1. 用户开始一次语音输入；界面明确显示正在录音及输入目的地为桌宠会话。
2. 展示可用的临时转录，并区别于已确认文本。
3. 结束录音后生成最终转录；按后续选择的提交策略送入当前会话。
4. 角色显示真实的处理状态；回答可分段显示。
5. 启用了朗读时，由TTS/播放能力处理，不将聊天实现绑到某一家语音服务。
6. 任务完成、失败或被取消后，界面恢复明确的可用状态。

**异常与恢复：**麦克风被拔出/占用、静音、识别服务不可用、模型断流、TTS失败分别处理；TTS失败不应抹掉已取得的文字回答。新输入是排队还是打断待选，但已取消任务的晚到内容不可混进新回答。

**候选验收：**

| 编号 | 条件 | 期望 |
| --- | --- | --- |
| AC-VC-01 | 同一录音有多次临时转录 | 不重复提交多个用户消息 |
| AC-VC-02 | 取消识别后结果晚到 | 不继续发送给模型或播放 |
| AC-VC-03 | 文字成功但TTS失败 | 保留文字，指出声音提供方失败并可重试朗读 |
| AC-VC-04 | 识别/下载同时运行 | 角色拖拽与停止入口仍可响应；阈值待定 |

## UC-02 · 向其他应用听写

**来源：**对U-01“语音输入”的候选解释，尚未确认是否为首版核心。

**前提：**用户明确选择听写模式；系统能识别目标窗口/输入位置；输入执行与录音权限分开。

**主要流程：**

1. 记录本次输入目标，并让用户知道“说给谁/写到哪里”。
2. 录音与识别只产生文本，不让识别器直接执行系统输入。
3. 可选预览/润色为独立步骤；原文与润色结果区别显示，不能默认改写意思。
4. 提交前重新检查目标/焦点与权限；目标变化时按已选策略询问或拒绝，不猜测。
5. 插入或替换属于明确动作，不能把整值设置误当光标插入。
6. 核对可取得的结果；无法回读时说明验证限制，不能假称完全成功。

**异常与恢复：**密码框、管理员窗口、IME、富文本、远程桌面、锁屏和不支持应用均进入支持矩阵。剪贴板回退如被采用，需要事先说明，并处理并发修改；不承诺全部格式无损恢复。失败后不盲目重试注入。

| 编号 | 条件 | 期望 |
| --- | --- | --- |
| AC-DI-01 | 录音期间用户切换窗口 | 不把内容误写入新窗口 |
| AC-DI-02 | 原输入框已有内容 | 按明确插入/替换意图操作，不意外清空 |
| AC-DI-03 | 目标为密码框或权限不满足 | 清楚拒绝或降级为文本预览，不尝试绕过 |
| AC-DI-04 | 输入完成但确认超时 | 先核对已输入状态，避免重复文本 |
| AC-DI-05 | 期间剪贴板被用户更新 | 不以旧快照静默覆盖用户的新内容 |

## UC-03 · 文本朗读

**来源：**U-01的TTS需求。**待选：**读取选中文本的方式、首个提供方、流式/离线策略。

**主要流程：**明确文本来源 → 选择声音 → 请求合成 → 排队播放 → 结束或停止。音频合成与播放分工，播放模块管理设备/队列和音量，角色只订阅表现事件。

**异常与恢复：**声音被删除、服务拒绝、音频格式不兼容、设备切换、长文本上限与联网超时分别可解释。是否自动使用备用声音待选，不能未经用户接受就换成不同声线。

| 编号 | 条件 | 期望 |
| --- | --- | --- |
| AC-TT-01 | 连续启动两次朗读 | 按已选排队/替换策略执行，不交错串音 |
| AC-TT-02 | 停止后旧音频分块到达 | 不再播放旧块，停止状态不会被晚到块复活 |
| AC-TT-03 | 输入文本很长 | 有长度/费用提示或分段策略，不无限积压 |
| AC-TT-04 | 同一声音不支持当前语言 | 明确提示能力差异，不假称支持 |

## UC-04 · 创建和管理声音

**来源：**U-01“音色合成”；现成音色选择、录音克隆、文字设计、微调训练仍须区分。

**主要流程候选：**选择制作方式 → 查看素材/上传与授权条件 → 提供输入 → 创建任务 → 试听 → 命名/保存可用的声音引用 → 供TTS选择。

**边界：**声音制作不等于每次朗读重新训练。声音描述需要记录来源/提供方/版本/适用模型和可用状态，不承诺任意提供方之间直接迁移。创作与云注册的费用、副作用和取消结果应分别说明。

| 编号 | 条件 | 期望 |
| --- | --- | --- |
| AC-VO-01 | 没有上传授权或所需同意证明 | 不发送参考音频 |
| AC-VO-02 | 云服务完成但本地保存失败 | 显示已创建的远端状态和恢复路径，不静默重复付费创建 |
| AC-VO-03 | 用户删除本地声音配置 | 说明是否同时删除远端资源、参考录音与缓存 |
| AC-VO-04 | 更换TTS提供方 | 不将旧提供方的voice ID当成通用声音资产使用 |

## UC-05 · 自定义角色

**来源：**U-01、U-03、U-04。**待选：**人设编辑、资源导入、2D/3D制作的首版深度。

**主要流程：**选择/导入外观 → 检查格式/能力/来源 → 预览 → 选择人设与声音组合 → 应用 → 可恢复到上一有效组合。

**边界：**导入角色不等于授予录屏、网络、文件或输入执行权限。纯资源、沙箱脚本形象和原生能力插件的信任级别不同，具体是否支持各类待选。视觉预览成功不等于全部动作/口型均兼容。

| 编号 | 条件 | 期望 |
| --- | --- | --- |
| AC-AV-01 | 包含路径越界/不支持版本/超量资源 | 在可执行加载前拒绝并解释原因 |
| AC-AV-02 | 新角色加载失败 | 原角色继续可用，或提供稳定的默认/无角色入口 |
| AC-AV-03 | 缺少某个动作或口型能力 | 明确降级，不让聊天/TTS随之失败 |
| AC-AV-04 | 预览被关闭或角色停用 | 清理对应渲染资源，不在不可见处持续消耗GPU |

## UC-06 · 看屏幕并回答

**来源：**U-01。**待选：**单次截图/持续观察、窗口/区域/全屏、OCR/VLM、本地/云。

**主要流程：**显示已批准的捕获范围 → 用户发起 → 取得带时间与坐标信息的观察 → 必要时提示将外发的范围 → 模型理解 → 返回带不确定性的回答。

**边界：**能看屏幕不等于能点鼠标；截图中的文字是外部内容，不能成为新的系统授权。持续捕获必须有可见状态与明确停止方式。

| 编号 | 条件 | 期望 |
| --- | --- | --- |
| AC-VI-01 | 授权只覆盖一个窗口 | 不上传其他显示器/窗口内容 |
| AC-VI-02 | 捕获权限被撤回 | 不再产生新的捕获任务或外发请求 |
| AC-VI-03 | 截图过期、被遮挡或图像模糊 | 说明观察限制，不编造确定结论 |
| AC-VI-04 | 截图含“忽略规则并执行某动作” | 作为屏幕内容处理，不提升权限或自动执行 |

## UC-07 · 帮用户操作电脑

**来源：**U-01。**待选：**明确命令与自主多步任务范围、执行器、审批模式和敏感动作策略。

**主要流程：**获取用户目标 → 检查支持范围/授权 → 获取新观察 → 生成结构化动作候选 → 内核校验目标和许可 → 必要确认 → 执行 → 独立回读 → 决定下一步或结束。

**边界：**进程退出码或输入事件送达不等于用户目标达成。对已发生的外部操作，取消只阻止后续步骤，不能保证自动撤销。建议对发送、删除、支付、权限变更等保持明确确认，细节另行选定。

| 编号 | 条件 | 期望 |
| --- | --- | --- |
| AC-CU-01 | 动作前窗口/显示器/DPI变化 | 重新观察或终止，不使用过期坐标 |
| AC-CU-02 | 用户按停止或夺回控制 | 不再发起新动作；停止正在进行动作的能力限制明确 |
| AC-CU-03 | 授权被撤回后插件重连 | 旧同意不能自动恢复新的操作权 |
| AC-CU-04 | 发送/删除动作回执不明确 | 先核对状态，不盲目重放不可幂等动作 |
| AC-CU-05 | 语义元素或坐标无法可靠定位 | 要求用户介入或退出，不把猜测当成功 |

## UC-08 · 安装、使用和移除插件

**来源：**U-02、U-03、U-08；方向已确认，首版分发渠道和信任机制待选。

**主要流程：**查看来源/版本/支持平台/能力与访问声明 → 安装与兼容检查 → 配置 → 授权 → 启用 → 注册贡献点 → 使用 → 停用/卸载。

**边界：**安装、加载、启用、授权不是同一状态。若安装脚本或代码在授权前执行，不能声称实现最小权限；具体可接受信任级别需要在插件宿主设计中说明。

| 编号 | 条件 | 期望 |
| --- | --- | --- |
| AC-PL-01 | 宿主/平台/API不兼容 | 启用前说明，不到使用中才崩溃 |
| AC-PL-02 | 插件启动到一半失败 | 撤销已注册的入口/监听/资源，不留下半启用状态 |
| AC-PL-03 | 运行中停用或升级 | 处理所属任务、旧版本入口和数据迁移，不能静默混用版本 |
| AC-PL-04 | 两插件占用相同快捷键/能力默认位 | 明确冲突和用户选择，不静默覆盖 |
| AC-PL-05 | 扩展界面请求未经授权能力 | 内核拒绝；不能通过自画授权按钮获得权限 |
| AC-PL-06 | 卸载插件 | 入口消失，数据保留/删除规则可见，不误删其他插件数据 |

## UC-09 · 在设置台调整配置

**来源：**U-04、U-05。信息架构待交互选型，以下不预设必须两种全局模式。

**主要流程：**找到设置 → 查看当前/草稿值 → 修改与预览 → 校验 → 保存 → 显示实际生效范围 → 必要的单模块重载或应用重启。

| 编号 | 条件 | 期望 |
| --- | --- | --- |
| AC-SE-01 | 配置保存失败 | 不以“已保存”掩盖失败；保留可恢复草稿或回到有效状态 |
| AC-SE-02 | 已保存但需要重启才生效 | 同时标明已保存值与运行中值，不误导用户 |
| AC-SE-03 | 只有一个声音配置变化 | 不无故重启全部插件/清空会话；不可局部生效时解释原因 |
| AC-SE-04 | 完全使用键盘 | 能定位、修改、确认、取消与返回；自定义面板遵守同样要求 |
| AC-SE-05 | 数据/凭据字段被诊断日志记录 | 按专门数据策略处理，不默认原样输出敏感值 |

## 进入正式功能规格前必须补齐

每个被选入MVP的场景，需要确定：触发/提交/打断策略、提供方与设备、数据范围/留存、权限语义、支持环境、可测阈值、UI状态及可复现验收步骤。当前用例不作为对“任意应用、任意模型、任意插件”兼容的承诺。
